## 3. 代码核验与第一阶段风险

本次以源码、包清单和已有场景文本为依据，未进行 Unity 编译或 Play Mode 验证。

| 现有实现 | 已核验事实 | 实施影响 |
| --- | --- | --- |
| NativePlayer / NativeEnemy / NativeCombat / NativeProjectile | 直接引用 NativeRunController，并通过该对象检查运行状态和访问其他组件 | 必须建立可独立运行的轻量上下文，不能直接整目录导出 |
| NativeRunController | Awake 要求 Quest、Dialogue、ECA、HUD 等引用；完成逻辑依赖 Narrative | 独立试玩应有自己的运行宿主，正式主线保留原宿主 |
| NativeEnemy | Chase、Orbit 两种移动方式；受击死亡后销毁，无显式死亡事件 | 模板可从已有机制提取；清敌完成必须基于真实死亡事件，不能将销毁视作击杀 |
| NativeFanAttack | 已有预警与三发扇形弹 | 首版远程模板可复用，需随敌人激活／暂停同步 |
| NativeBossController | 直接依赖 PlagueSurvivor.BossArenaConfig 及旧视觉辅助代码 | 仅提取实际使用的视觉资源与辅助实现，不打包旧 BossArena 运行系统 |
| NativeObstacle | 视线查询和弹丸查询对标记组件的获取层级不同 | TilemapCollider 挂载与查询必须统一，避免能碰撞却能穿墙射击 |
| NativeChunk / NativeMap | 南北端口、两个北侧实例与特定门字段 | 新工具包另建通用 Chunk／门集合；保留旧场景接线 |
| NativeGame | 当前未找到本目录 asmdef | 新 asmdef 不能直接依赖默认 Assembly-CSharp；共享部分要先正确划分 |

仓库版本证据：Unity 2021.3.27f1c2、URP 12.1.12；manifest 中 TMP 3.0.6、Test Framework 1.1.33；lock 中 Tilemap 1.0.0、Tilemap Extras 2.2.5。上述是仓库快照，干净工程仍需验证依赖能正确安装，不能假设 unitypackage 自动安装 UPM 包。

    Level/           战斗区域、遭遇状态、出口、独立运行宿主
    Binding/         局部端点、测试绑定；不引用正式任务与叙事

    Authoring/       Chunk／地图／关卡制作面板与场景工具

    Packaging/       工具包／作品包导出与接收检查

  Samples/           单块、拼接、战斗与完整示例

Assets/EchoUserContent/<author>/<work>/

  Chunks/ Actors/ Art/ Levels/ Bindings/
Assets/NativeGame/ToolkitIntegration/
  主项目专用上下文适配与正式叙事绑定

目录名为建议；`Documentation~` 与 Markdown 在导出／导入后的保留方式必须实测，不依赖命名约定猜测。若 Unity 导出不能可靠包含 Skill 文件，改为可随包保留的载体并在显式安装时还原，不能交付缺失的 Skill。

程序集至少隔离 Runtime、Editor、测试。Runtime 不引用 UnityEditor、NativeGame、PlagueSurvivor、CyberCity 或主线资源。Editor 只向 Runtime 依赖。默认程序集中的主项目适配器可以引用工具包 Runtime；不得形成反向依赖。类型拆分期间保留现有组件 GUID 和序列化引用。

### 4.1 共享战斗代码迁移策略

优先提取行为到工具包公共实现，原 Native 组件保留序列化外壳和兼容入口，委托公共逻辑执行。不要一次性给整个 NativeGame 添加 asmdef，也不要建立长期独立演进的两份战斗实现。

先用玩家、一个追击敌人和弹丸证明上下文可分离，再迁移远程敌人和 Boss。若现有 MonoBehaviour 拆分复杂，可在技术切片内临时比较替代实现，但 G1 必须确定唯一共享行为来源及原场景回归路径。禁止为使测试场景能跑而伪造完整主线 Quest／Narrative。

运行上下文只提供实际所需能力，例如运行状态、当前玩家、战斗服务与死亡回调。依赖显式注入，不使用 FindObjectOfType 选择任意宿主；不建立全局服务定位器或独立世界模拟。

### 4.2 状态归属

| 状态 | 唯一拥有者 |
| --- | --- |
| 玩家／敌人生命，Boss 外壳与最终死亡 | 各 Actor |

## 5. 制作数据模型

使用 Unity 序列化组件与 ScriptableObject；运行时可变状态不写回共享配置资产。以下为 G0 后冻结的建议模型。

| 模型 | 最小字段 | 约束 |
| --- | --- | --- |
| ToolkitVersion | 工具版本、内容格式版本、Unity／UPM 依赖、模板版本 | 首版默认精确匹配；兼容列表必须经测试证明 |
| StandardPlayerProfile | 来源版本、移动／碰撞／战斗参数、Prefab | 创作者只读，不随作品修改 |
| ChunkDefinition | 稳定内容 ID、N、四边接口、主题、图层引用 | N∈[3,32]，正方形，单位缩放、无旋转 |
| EdgePort | 边、enabled、offset、width | 半开区间 [offset,offset+width)，0≤offset，终点≤N |
| ChunkPlacement | Chunk 引用、整数 x/y | 不复制共享资源，不产生重叠占地 |
| LevelDefinition / LevelRoot | 内容 ID、实例 ID、地图、区域、出生点、出口、端点 | 持久内容 ID 与运行实例 ID 分离 |
| EncounterDefinition | 局部 ID、区域、模式、目标 Actor、门引用、触发方式 | 清敌／Boss 至少具有有效目标，区域不相交 |
| Endpoint | 局部 ID、类型、目标引用、说明 | 局部 ID 唯一；不存主线任务编号 |
| SandboxBinding | 测试必需遭遇、测试终点、占位交互 | 只在 Sandbox 模式订阅 |
| WorkManifest | 作者／作品 ID、包类型、根资源、版本、公共依赖、内容指纹、接口清单 | 不携带凭据，不声称包含未打包依赖 |

边偏移统一约定：北／南边从左向右，东／西边从下向上。地图矩形按 [x,x+N)×[y,y+N) 表达；边界接触不算占地重叠。所有空间计算使用整数格拓扑，最终再验证真实物理通行。

Prefab 建议层级：`ChunkRoot → Grid → Ground / Obstacles / Decoration / Overhead`。Ground 表示存在的地面；Obstacles 使用 TilemapCollider2D 和统一障碍标记。动态门位于关卡层。跨格装饰允许视觉超出占地，碰撞不应未经声明侵入邻块；首次规格冻结明确边界策略。

## 6. 地图制作与校验实现

### 6.1 编辑工作流

制作面板顺序为：选择作品 → 创建 N×N Chunk → 设置接口 → 绘制 Tilemap → 检查 → 加载单块／邻块试玩。地图装配工具只提供整格吸附、占地显示、接口连线和问题定位，不自动生成缺失道路或填空。

首版默认 Point 采样、无 mipmap 的像素素材配置，在 32 PPU 基础上验证像素显示；不替换主工程渲染管线配置。建筑朝向变体由独立资源生成，生成前预览，保留原 Prefab 和 GUID。

### 6.2 端口拓扑

1. 将各 Chunk 边接口换算到地图整数格边界坐标。
2. 只匹配共线、相对朝向、两侧占地相接的边。
3. 计算接口区间交集；大接口可由多个小接口覆盖，覆盖区间不得重叠。
4. 检查匹配双方实际通行带；不能只比较端点 Transform 距离。
5. 将未覆盖接口段标记为需要实体封闭；若已配置边界阻挡则通过，否则报错定位。

Chunk 资产校验允许声明开放端口；它尚无邻居，不能仅因未配对而判错。完整地图校验才要求端口对接或封闭。单块测试场景以明确的测试边界夹具封闭未使用接口；夹具不写回作品。

### 6.3 通行与封闭

采用两层验证：整格地面／障碍图用于快速拓扑检查，标准玩家体积下的 Physics2D 重叠与扫掠用于判定碰撞净空。中心点可走不代表玩家能通过；对角擦角和跨块接缝必须验证连续路径。

验证所有已开端口的可通行带属于同一连通分量；装饰性隔离区不强制可达。地图上的玩家出生点、必需战斗目标和终点需按对应门状态检查合理可达性。分别检查初始、战斗封门及完成开门状态，不能因为初始锁门而要求玩家提前到达终点。

封门校验在隔离的验证场景中模拟门关闭，不修改作者场景。判断玩家是否还能从战斗区域逃到外部，以及所有实际触发位置关闭门后是否安全；仅测区域中心不足以通过。运行时启动战斗前再次验证玩家不与门碰撞，必要时延迟关门到玩家安全进入，不能夹住或传送玩家掩盖错误。

碰撞、视线、子弹统一识别障碍，TilemapCollider 所在层级必须能被三者一致检索。处理 Tilemap 变更后物理几何尚未更新的时序，并通过测试证明，不依赖编辑器偶然刷新。

### 6.4 AI 修改保护

保存每次 AI 写入的基线快照／指纹；后续修改使用“上次 AI 基线、当前内容、新方案”三方比较。当前内容与基线不同的格子、属性和对象视为人工修改，默认保留并报告冲突。没有基线的现存资源视为人工内容，不推断可覆盖。

提供变更预览、局部应用及 Undo；记录作品内的生成来源。整块重建必须来自明确用户指令。首版实现聚焦 Tilemap 格子、端口、装饰对象和基本属性，不扩展为通用版本管理工具。

## 7. 战斗编排与生命周期

建议区域采用简单 PolygonCollider2D 触发轮廓，矩形为快捷创建方式；这是可替换的工程默认值，G0 验证后冻结。区域禁止自交、非零面积重叠；边接触可允许。多个区域同帧命中时按稳定标识去重，不能重复启动战斗。

清敌／Boss 遭遇状态为 `Ready → Active → Completed`。死亡后运行宿主停止战斗；重开创建新关卡实例，不将销毁时的事件当作完成。自由交战不占用必须完成集合，其 Actor 随运行宿主正常战斗。

- Ready 中的清敌目标／Boss 不攻击也不受误触发伤害；激活时创建或启用一次，策略在模板内一致。
- 目标死亡产生带 Actor 实例身份的真实事件；清敌列表逐个记录一次。销毁、禁用、卸载、编辑器删除不产生击杀事实；Active 中目标无故丢失应报故障，不自动判胜。
- Boss 完成只来自经过距离、窗口与运行状态校验的核心互动，弹丸不能直接完成。
- 激活必须先验证依赖并返回成功结果，再提交遭遇开始与封门；若激活失败，撤销本次临时门锁且不提交任务开始。现有 void ActivateEncounter 不能直接作为成功证据。对首次启动、重复启动和配置缺失分别测试。
- 撤离只改变玩家位置，不禁用／重建遭遇，不重置血量与阶段。
- 主动停止、死亡、重开、卸载清理弹丸、预警、订阅与活动对象登记。静态 Actor 集合如保留，必须按 Run／关卡实例过滤并正确清空。
- 一个门首版只归属一个遭遇的封门控制，避免重叠锁；正式剧情动作通过同一 Map 接口处理，不能直接 SetActive 绕开门状态。

建议将门的通行许可与战斗锁区分为 Map 内部输入：战斗锁未释放时，剧情开门请求不能提前解除战斗封锁；完成时解除战斗锁并按已配置的出口规则开放。此冲突策略在 G0 记录为工程决定并验证正常“完成后开门”流程，不增设第二套门状态。

普通敌人首版候选为追击接触型与 Orbit + FanAttack 远程型；保留原行为和标准数值来源。Boss 保留现有机制和窗口失败重试。参数须拒绝 NaN、Infinity、负生命／非正攻击间隔等非法值；不允许作品覆盖标准玩家参数。

参数面板只展示模板实际支持的能力：接触敌人没有独立攻击间隔，当前伤害节奏受玩家受击无敌时间约束。现有敌人绕障是短距离触须转向，不是通用路径规划。地图拓扑通过不等于敌人能完成复杂追击；内容验收必须实际验证敌人行为，首版不擅自新增寻路系统，受现有行为限制的地图应报告问题并调整布局。

## 8. 叙事接口与绑定

### 8.1 最小协议建议

G0 结合现有主线冻结首批接口。建议事件：`RegionEntered`、`InteractionConfirmed`、`EncounterCompleted`、`ExitReached`；动作：`ActivateEncounter`、`SetDoorOpen`、`SetInteractionEnabled`、`UnlockExit`。

事件携带运行 ID、关卡实例 ID、端点 ID、事件类型、事件序号及必要 Actor 引用。内容 ID 用于识别资产，不单独用于运行时寻址。跨局事件不可继续消费。事件通道为关卡／Run 局部，不建全局字符串消息总线。

普通进入事件可以重复发生；完成事件只提交一次。是否记录“一次绕行”由 Narrative 决定。Binding 不重复保存任务完成状态；仅保留订阅和必要的派发防重信息。

动作返回明确结果：成功、已满足、条件不满足、目标缺失、模式不允许。动作在调用时复查运行与实例条件，不以界面按钮可用状态作为唯一保护。进入触发与剧情激活属于同一个遭遇入口，均经过状态机和条件许可，不重复生成目标。

### 8.2 模式与接线

RunHost 启动前显式选择 `Sandbox` 或 `Integrated`。模式在本局固定；切换需重新启动，避免残留订阅。预览默认 Sandbox，无法访问正式 Narrative。

SandboxBinding：占位终端对白、必需遭遇集合、测试终点与重开。IntegratedBinding：位于主项目适配目录，接收局部事实，调用真实 Quest／Narrative／Dialogue／Map；必须先完成订阅再激活关卡。

正式模式缺失必需绑定时报告错误并停止启动，不静默退回测试模式。正式模式停用测试完成逻辑，但保留必要的战斗机制和场景运行组件。

接口清单由序列化端点生成，包含 ID、类型、对象路径、说明、必需／可选绑定。变更端点 ID 视为接口变更，列出对现有绑定的影响；不能静默重生成稳定 ID。

首个集成示例在新增验证场景中完成真实区域／互动事件到主项目状态的接线，不改写已保存 NativeDemo 的剧情。若需要扩大现有任务 API，仅做有实际用例的窄范围扩展，并回归现有任务；不要创建完整剧本图编辑器。

## 9. 编辑器与测试体验

主入口建议 `Echo / Level Toolkit`，提供作品设置、内容创建、地图装配、战斗绑定、校验结果、试玩、导出七个入口。优先标准 Inspector、Scene Handles 和轻量 EditorWindow，避免先做复杂节点编辑器。

结果行统一包含严重级别、稳定错误码、对象引用、地图格坐标／端口、说明和修复建议；点击能选中问题对象。批量运行提供同源的机器可读报告，禁止 UI 与 CLI 各写一套校验规则。

最少测试场景：ChunkPreview、MapPreview、CombatPreview、SampleLevel。试玩必须有 WASD、Space、E、死亡／重开、通关反馈；无需复制主游戏手机与正式剧情 UI。所有生成／保存场景操作必须显式指定输出路径，不修改当前打开的 NativeDemo。

## 10. 导出、依赖与接收

### 10.1 依赖分类

从作品根资源遍历实际依赖，并分类：作品自有资源、工具包公共资源、UPM／引擎资源、未声明外部资源。前者打包；公共资源记录精确版本／身份；UPM 依赖写清单；未声明外部依赖阻止导出并定位。

不要使用无过滤的 IncludeDependencies 把 NativeGame 或旧原型整树拉入包。公共资源不随作品重复导出。作品不得携带自定义运行脚本，行为通过已支持模板配置；新增行为先升级统一工具包。标准角色／公共素材若被作者修改，必须报冲突，不能伪装为标准依赖。

Skill 源文件与说明属于工具包资源，显式安装到 Codex 可发现位置，安装时展示目标和覆盖差异；Unity 打开工程时不得自动修改用户全局配置。不能把 Unity MCP、CLI 或用户 Codex 设置直接打入游戏包。

### 10.2 导出与验收绑定

一键导出内部流程：验证 → 确认当前内容已有人工验收记录 → 收集依赖 → 生成接口清单和 Manifest → 导出暂存包 → 检查包清单 → 发布产物路径。

人工记录绑定内容指纹与工具版本。几何、配置、接口或依赖变化使旧验收失效；不得仅凭永久勾选框绕过验收。导出失败保留明确错误，不留下误标为成功的包。

### 10.3 接收与版本

接收工具先读取作品 Manifest／包清单，在写入目标资源前比较路径、GUID 与版本。Unity 原生导入可能覆盖资源，因此推荐从工具入口预检或在隔离工程预览；导入后检查不能被声称为覆盖前保护。

新作品不得覆盖其他作者作品或公共工具。相同作品 ID 的更新显示差异，由用户显式接收；默认不做自动替换、合并或迁移。路径冲突、GUID 冲突、缺少公共依赖、版本不匹配均阻止正式接入。

工具包不能通过 unitypackage 假定已配置 Input Manager、图层、URP、字体或 UPM。环境检查列出差异；提供只在独立测试工程显式运行的设置向导，保留原设置和变更记录，不覆盖主工程 ProjectSettings。

## 12. 风险与处理

| 风险 | 提前控制 | 失败处理 |
| --- | --- | --- |
| 抽取战斗破坏 Native 场景 | 保留外壳／GUID，小步迁移，行为对照 | 回退该任务变更，缩小抽取面后重做 |
| 1 格接口实际卡角色 | G0 实体角色转角／接缝测试 | 报告数据并请求规格调整，不私改角色 |
| 地图校验只有格子理论正确 | 真实碰撞扫掠和失败夹具 | 未证明的情况标为待核验，不能报告通过 |
| 非封门 Boss 撤离时被重置 | 生命周期与场景激活独立 | 修正停用路径，测试健康／阶段保持 |
| UPM／字体／渲染隐藏依赖 | 最早建立干净工程 | 补齐明确安装流程或缩减不必要依赖 |
| AI 覆盖精修 | 基线比较、预览、Undo | 不自动覆盖冲突；保留作者修改 |
| 包覆盖主项目资源 | 导入前清单和身份检查 | 阻止冲突包正式接入 |
| 多个task thread同时改场景／配置 | 单一集成负责人与 Unity 写锁 | 串行保存，禁止手工合并 YAML 猜测结果 |

主控先处理风险验证，再追求编辑器外观与更多素材。发现原型能力不足应报告具体差距，不把新增玩法藏进“适配”任务。
