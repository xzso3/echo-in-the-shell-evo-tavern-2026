## 本轮最高执行优先级：极致速度

用户已明确要求尽可能忽略测试，只保留最必要检查。默认不编写自动化测试套件、不跑完整A/B矩阵、不安排专门评审代理、不等待第二作者或全面人工验收。只完成ACCEPTANCE.md的S1编译启动、S2核心短流程、S3一次包往返、S4一次正式接入；已有操作结果复用，仅在变更影响或失败时重跑。其余检查后置，不再向用户重复申请省略测试。

功能仍须完成，尤其本体接入、校验器、精修保护和导入防护。省略测试不等于删除功能，也不等于将未测写成通过。各文档中旧的全面测试要求按本节覆盖执行。

## 目标

交付可在独立 Unity 工程使用的关卡制作工具包、单项与完整关卡作品包、五个制作 Skill、完整示例、主游戏正式叙事接入与可核查验收证据。工具包独立成功不能代替本体成功；必须完成 NB-01～NB-04 和所有对应共享能力。

## 启动顺序

1. 记录当前分支、基线提交、用户未提交修改与打开的 Unity 工程。保护所有无关修改，不清理或提交他人工作。
2. 建立 STATUS.md，列任务状态、threadId、hostId、工作树／分支、基线SHA、model／thinking／priority核验状态、允许路径、依赖、Unity使用者和下一个关口；全部先标未执行。
3. 按 W0 将只读核验分给 Sol，主控汇总 KT-00。Unity 探针串行，先冻结接口和技术结论，再展开实现。
4. 在 DECISIONS.md 记录技术选型与证据。1格净空、模板、程序集、独立依赖、门状态、稳定ID、事件动作、Skill分发方式均要有结论。产品参数必须变化时报告影响并询问用户，其余独立工作继续。
5. 按并行文档分波派发，先做可运行纵向切片，再完成制作和交付流程。

## 独立 task thread 调度与 priority

参考 codex://threads/01a0ca99-e997-7733-9a45-d4ee7b146ff8 的主控方式：最多5个独立执行task thread并行，INT-LT集成任务占一个名额。执行、集成及返修任务明确使用 model: "gpt-6-sol"、thinking: "xhigh"，所有task thread（含主控）要求实际请求 service_tier: "priority"。不使用subagent／spawn_agent，不允许执行任务嵌套子代理。

主控只做文档、调度、核验与沟通，代码、Unity和Git集成由执行任务承担。授权启动后使用create_thread创建独立任务，send_message_to_thread续派／返修，wait_threads等待；遵循工具当前schema、项目及工作树选择规则。每次派发包含：任务ID、目标、输入基线、允许／禁止修改路径、依赖接口版本、具体交付物、验收ID、Unity使用约束和回报格式。

priority必须在任务实际配置生效，不能只写在prompt里。当前create_thread／send_message_to_thread无service_tier参数，不能编造字段；启动前核对受支持的宿主／任务设置，新建和续派后记录有效配置证据。当前本机默认已观察为priority，仍需防止任务覆盖。若无法配置或确认，报告缺口，禁止静默降级或声称已生效。

只有冻结接口后才让消费者并行实现。共享文件、Packages、ProjectSettings、NativeDemo和最终场景保存由独立INT-LT任务统一处理。同一checkout不可同时打开多个Unity会话；执行任务不终止用户编辑器进程。可用独立工作树隔离代码，但不要手工拼接冲突场景YAML。

## 实现重点

- 共享战斗逻辑唯一来源，Native保留兼容入口与资源GUID；工具Runtime不依赖Native叙事或旧原型。
- Native本体补齐：Tilemap接收、多区域、多门、真实敌人死亡、Boss多目标交互、运行实例身份、输入与支援兼容、任务／叙事最小适配、正式生命周期。
- Boss激活失败不能锁门或提交已开始；对象销毁不能冒充敌人死亡。
- 混合Chunk、宽端口分段连接与物理净空同时检查；现有简单绕障不被宣称为完整寻路。
- 独立测试与正式绑定互斥；导入／预览不提交主线状态；多实例事件不串线。
- 保护手工精修，依赖导出白名单、导入前冲突检查、内容指纹关联人工验收。
- 不重跑已保存NativeDemo的一次性菜单；新增集成场景先验证，再做必要兼容回归。

## 质量和进度

每项任务交diff和实现摘要，主控快速核对后继续集成；不要求逐任务测试报告。将S1～S4合并到最终会合点执行；G4及全量A/B后置。空闲Sol继续开发，不安排常规独立评审轮次。

每波报告：已完成并验收的能力、仍缺的本体能力、阻塞依赖、实际产物与下一波计划。时间优先用于可交付功能，减少美化、测试编写和报告整理；不删本体接入，S3包往返仍保留。

禁止伪造测试／人工记录。S1～S4完成即可交付本轮快速版本，明确完整人工和第二作者验收后置。不得因为后置检查未做而停住开发交付，也不得未经用户要求新建定时任务。
