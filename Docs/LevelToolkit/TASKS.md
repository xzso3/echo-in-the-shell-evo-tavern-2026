# 任务拆分与委派规范

状态：全部待执行。本轮执行速度优先模式：任务卡中的 A/B 验收编号和自动测试／夹具交付要求降为后置参考；只要求功能交付及 ACCEPTANCE.md 的 S1～S4，不创建全套测试或等待第二作者验收。关联：[开发方案](DEVELOPMENT_PLAN.md)、[验收矩阵](ACCEPTANCE.md)。

本体任务 NB-01～NB-04 见 [本体补齐计划](NATIVE_GAP_PLAN.md)，与 KT 任务共同构成完整范围。并行执行采用 [分波安排](PARALLEL_EXECUTION.md)，不得仅完成 KT 就宣布整体完成。

## 1. 负责人及修改规则

主控只负责文档、依赖、接口冻结、派发、核验与用户沟通；实现任务交给独立Sol任务，代码、Unity和Git集成交给INT-LT等执行任务。采用独立Codex task thread，不使用subagent。执行任务统一gpt-6-sol／xhigh／priority，最多5个并发，含INT-LT集成任务；每项任务一个负责人。

集成负责人独占：NativeDemo、新增集成场景最终保存、Packages、ProjectSettings、共享接口、公共 Prefab 最终版本、发布版本号。其他任务若需修改这些内容，提交具体请求或补丁，由独立INT-LT任务集成。

每次派发指定允许路径、只读路径、基线提交、依赖版本、验收用例、禁止事项和交付格式。独立代码任务可并行；同一工程的 Unity 编辑器／批处理只有一个使用者。不要启动第二个 Editor 打开已被使用的 checkout，不结束用户的编辑器进程。

建议独立工作树承载代码任务，分支使用 `codex/` 前缀。工作树不代表 Unity 资源可以随意并发修改；依赖安装、许可证及 Editor 访问均由主控协调。主控不提交或清理与本任务无关的用户修改。

## 3. 任务卡

### KT-00：基线核验与技术冻结（先串行）

- 输入：需求、本文、NativeGame 源码与当前工程。
- 工作：记录 Git 基线／脏文件；读取场景真实标准角色参数；验证 1 格直路、转角、接缝；追踪独立战斗依赖；确认模板、区域几何、UPM、Skill 分发方式；验证共享程序集提取路径。
- 交付：`DECISIONS.md`、`BASELINE.md`、依赖清单、最小技术探针及结果。探针放隔离目录，不修改 NativeDemo。
- 决策项：格子世界尺寸、角色快照、两类普通敌人候选、Boss 资源提取、区域形式、共享类型边界、门冲突策略、最小事件／动作、包版本与Skill载体。
- 验收：A01～A03 的基线部分；所有未知项有实测结论或明确阻塞。若规格需变化，先向用户报告。
- 禁止：运行一次性旧场景菜单；把默认代码数值当实际 Prefab 值；边核验边扩写整套框架。

### KT-01：公共数据、身份与运行边界

- 依赖：KT-00。
- 允许：Runtime/Foundation、程序集定义、共享接口测试。
- 工作：定义 Chunk／接口／作品标识、运行实例身份、轻量上下文、标准角色配置和报告模型；明确所有权和序列化兼容策略。
- 交付：最小可编译 Runtime／Editor／测试程序集，公共 API 表与迁移说明。
- 验收：新 Runtime 不依赖默认 Native 程序集和旧原型；两实例身份隔离；共享 ScriptableObject 不承载本局状态。
- 禁止：全局服务定位器、全玩法 Schema、直接移动现有组件导致 GUID 或序列化失效。

### KT-02：共享战斗与独立试玩宿主

- 依赖：KT-01。
- 允许：Runtime/Combat、独立 RunHost／输入／测试 UI、模板；Native 兼容修改由集成负责人应用。
- 工作：依次抽取标准角色、伤害／弹丸、追击敌人、Orbit 远程敌人、Boss；提供真实死亡事件；解除 BossArenaConfig 运行依赖；保留原机制与原主线入口。
- 交付：独立 CombatPreview、标准参数快照、敌人和 Boss 模板、公共资源许可清单、原主线回归证据。
- 验收：A10～A13、A22；敌人真实击杀一次、Boss 核心判定、死亡清理、不引用完整 Narrative；现有 Native 基础行为保持。
- 禁止：为测试复制整套主线；改变 Boss 玩法；长期双份战斗实现；伪造死亡或胜利。

### KT-03：Tilemap Chunk 与地图制作

- 依赖：KT-01。
- 允许：Runtime/Map 的 Chunk／装配模型，Editor/Authoring/Map，Chunk 样例资源。
- 工作：3～32 混合尺寸、整数摆放、四边连续接口、主题分类、Palette／RuleTile 接入、变体生成、Tilemap 图层、人工修改保护和 Undo。
- 交付：单块创建、地图装配、接口可视化；3、奇偶混合和32格样例；可恢复的局部修改流程。
- 验收：A04～A06、A09；Prefab 独立实例，不烘焙，不直接旋转镜像，手工精修不丢失。
- 禁止：自动填空／补路；静默重建；全局改主工程图层或渲染设置。

### KT-04：地图、碰撞与封闭校验

- 依赖：KT-01、KT-03；封门最终验收依赖 KT-05。
- 允许：Editor/Validation 的空间规则、测试夹具和报告渲染。
- 工作：占地、端口区间覆盖、未连接段阻挡、体积通行、格内外可达性、出生点／门／终点阶段可达性；输出稳定错误码与定位。
- 交付：编辑器和批处理共用的校验入口，成功／故意失败夹具。
- 验收：A04～A08、A15；格子拓扑与真实物理分层验证，Chunk 开放端口与地图边界检查不混淆。
- 禁止：只有中心点洪泛就报告可通行；仅检查门对象存在就报告封闭。

### KT-05：战斗区域、门和完成流程

- 依赖：KT-02、KT-06；使用 KT-01 的固定模型。
- 允许：Runtime/Level、Runtime/Map 的门集合、Editor/Authoring/Encounters。
- 工作：跨 Chunk 区域、三种模式、一次启动、真实目标完成、可撤离不重置、门状态、必需集合、终点与整局重开。
- 交付：配置界面、状态机测试、跨块战斗样例、封门和不封门场景。
- 验收：A14～A17；角色真实进入、重复进入、目标销毁、死亡、门冲突和重开场景全部覆盖。
- 禁止：用对象消失计击杀；区域 Exit 触发重建；实现波次或持续刷怪。

### KT-06：关卡端点、事件动作与模式

- 交付：接口说明、生成清单、同关卡双实例测试、模式切换和缺失绑定诊断。
- 验收：A18～A20；事件来自真实组件，卸载解除订阅，正式模式不回落测试模式。
- 禁止：把任务／同步分数塞进关卡资源；全局字符串事件总线；建立第二份叙事状态。

### KT-07：主项目正式叙事适配
