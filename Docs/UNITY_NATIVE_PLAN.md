## 交付与环境

使用本机现有 Unity 2021.3.27f1c2、URP 12.1.12，不升级工程。当前仅发现 MacStandaloneSupport；执行任务立即核查并安装该版本 Windows Mono 构建支持，先验证可用性，不能把模块目录存在视为构建通过。用户已确认有 Windows 电脑可接收试玩。Mac 上编译或运行不能替代 Windows 启动验收。交付完整 exe、Data 及依赖目录的 zip、操作说明和已知限制。

## 本轮范围与变化

保留核心设计的约五分钟单人叙事动作体验：WASD 移动、Space 自动开火/停火、E 互动、Tab 虚拟手机；交战或绕行、记忆与支援授权、Boss 决定性动作、基于本局记录的结局和重开。

- 先交一条从开局到结局的完整路径，再补四象限结局、本地指挥官、三页签虚拟手机、支援与新生拳击。不是先完成框架再制作游戏。
- 最小内容：一张紧凑地图、一条绕行、一种普通敌人、三段固定记忆、一个 Boss 遭遇、一个最终节点。先做医疗支援与弱点解析；更多敌人、支援和装备变化按剩余时间决定。
- 四象限结局优先用不同短文本收束，新生保留玩家第一拳、协程自主最后一拳、黑屏约两秒后虚拟手机接续。行为屏幕读取真实本局记录。
- 延期建议（暂不排入本轮）：在线 LLM、外置手机配对、真实全服服务/贡献/继承链、ARG、语音、复杂存档恢复、完整装备养成、精细演出、全程不开火 Boss 路线。保留长期产品目标，不冒充已实现；网络页显示未连接，回声标为系统初始回声。
- 正式 Boss 身份与美术未定，允许明确标注开发占位复用测试战斗；WARDEN-01 不进入正式剧情设定。
- 停止新建独立引擎、适配层、通用 ECA/Schema、内容工具链、四 Chunk/第二内容包、框架冻结和双宿主一致性工程；既有源码、素材、算法及证据全部保留，按收益复用。

## 足以开发的组件与状态

| 组件（可按现有脚本合并） | 职责与唯一状态 |
| --- | --- |
| NativeRunController | 场景内单例 MonoBehaviour；流程枚举、任务结果、记忆、同步/差异、一次性事件、结局。重开重载场景，不建独立运行引擎 |
| PlayerController / Health / Weapon | GameObject 上保存移动、生命、冷却与开火状态；Unity 输入采样，Rigidbody2D/Physics2D 优先；现有可用算法直接复用，不为迁移重写 |
| Enemy / Projectile / BossController | 各自生命与攻击阶段，协程与 Unity 时间驱动，Collider2D 命中；Boss 窗口可重复出现，E 才完成决定性动作 |
| Interaction / Objective | 具体节点 MonoBehaviour；范围内 E 执行，完成后通知 RunController。任务完成和计分只有一个所有者，不建通用任务框架 |
| PhoneUI / Commander / Support | Canvas 直接引用 RunController 和玩家；固定主题对白、支援合同、接受/拒绝。效果成功才提交授权；按钮禁用与合同终态防重复；手机不暂停战斗 |
| EndingController / HUD | 读取本局状态；提示、胜败、真实记录、拳击协程与重开按钮；只呈现，不重复维护分数 |

输入路由在一个具体组件集中处理：文本焦点屏蔽玩法输入；新确认才接受合同；Tab/E/Space 不沿用原型地图/背包/对话冲突。原型装备 UI 可暂不接入。数值、对白、节点引用用 Inspector 序列化字段，复用配置可用 ScriptableObject，不要求 JSON。

## 场景、资源与启动

新增独立 `Assets/Scenes/NativeDemo.unity`，尽量一个场景容纳入口、探索区、安全节点、Boss 区和结局 Canvas。根节点建议 Run、World、Actors、UI；玩家、敌人、弹丸、互动点用具体 Prefab。必要时复用原型脚本，但避免旧全局自启动在新场景重复生成世界。

直接复用 Assets/CyberCity、Assets/Art/Generated 与现有角色/预警/UI 素材，保持 GUID；拖入 SpriteRenderer、Animator、AudioSource 和 Inspector 引用。不新建资源 ID 适配层，不删除历史场景。首次构建仅包含新入口及确实需要的场景。

启动：场景加载 → Awake 连接引用 → Run 初始化本局 → 生成/启用玩家与 HUD → Start 发布首个目标 → 正常 Update/FixedUpdate/协程驱动 → 目标推进 Boss 与最终节点 → 结局/死亡可重开。必要缺失引用直接显示可定位错误并修复，避免建设诊断框架。

## 验收与调度

开发期仅必要编译、启动、当前关键路径冒烟；无法编译/启动或阻断当前开发立即修。功能先行，其余缺陷记到下表，最后人工试玩筛选。不开自动化测试体系、不补边界用例、不重复全量验证。原 G1/G2/G3 为 not_run，不适用于本轮放行。

先 U0 与 U1 两项并发；U0 只检查环境/保存分支与文档，不占运行编辑器，U1 独占 Unity。U1 交付后由 U0 执行 U2；第二槽只做边界明确的玩法内容。共享场景/项目设置/集成分支始终单一执行任务拥有。交付只需提交号、构建路径、做过的检查、未测项与限制。

最终人工清单：解压启动；WASD/Space/E/Tab；真实走完至少一条流程；Boss 无永久卡死；死亡重开与结局重开；关键文字/资源可见。四结局等仅在实际走过后标通过。不能用编辑器、脚本设状态或历史证据替代实际 Windows 玩家操作。
