# Unity 原生交付方案

生效：2026-09-23；本次修正保留 ECA 与原系统划分，仅取消独立引擎等运行要求。用户本轮决策优先于独立 .NET 引擎、双宿主及原 P1 流程。目标为 **2026-09-24 11:00（UTC+8）交付 Windows x64 可执行游戏**，开发速度与交付优先。主控只做文档、调度和验收；实现与 Git 集成交给执行任务；Windows 构建由用户手动完成，最多并发两项，Unity 槽一项。

## 交付与环境

使用现有 Unity 2021.3.27f1c2、URP 12.1.12，不升级工程。用户已确认 Windows 构建环境安装完成，并明确自行手动构建；执行任务只做开发，不安装构建模块、不自动打包、不建设构建体系。用户有 Windows 电脑可进行实际试玩。开发任务提供可打包源码、入口场景、需要的 Build Settings 和操作说明；用户生成 exe、Data 及依赖目录并确认实际启动。Unity 编译/场景启动仅作为开发冒烟，不能替代 Windows 验收。

## 本轮范围与变化

保留核心设计的约五分钟单人叙事动作体验：WASD 移动、Space 自动开火/停火、E 互动、Tab 虚拟手机；交战或绕行、记忆与支援授权、Boss 决定性动作、基于本局记录的结局和重开。

- 先交一条从开局到结局的完整路径，再补四象限结局、本地指挥官、三页签虚拟手机、支援与新生拳击。不是先完成框架再制作游戏。
- 最小内容：一张紧凑地图、一条绕行、一种普通敌人、三段固定记忆、一个 Boss 遭遇、一个最终节点。先做医疗支援与弱点解析；更多敌人、支援和装备变化按剩余时间决定。
- 四象限结局优先用不同短文本收束，新生保留玩家第一拳、协程自主最后一拳、黑屏约两秒后虚拟手机接续。行为屏幕读取真实本局记录。
- 延期建议（暂不排入本轮）：在线 LLM、外置手机配对、真实全服服务/贡献/继承链、ARG、语音、复杂存档恢复、完整装备养成、精细演出、全程不开火 Boss 路线。保留长期产品目标，不冒充已实现；网络页显示未连接，回声标为系统初始回声。
- 正式 Boss 身份与美术未定，允许明确标注开发占位复用测试战斗；WARDEN-01 不进入正式剧情设定。
- **保留：Unity 内部模块化玩法框架、ECA 事件/条件/动作编排、Entity/Map/Actor/Combat/Interaction/Quest/Dialogue/Level 的职责与状态归属。** 定位类似 QFramework，但不要求引入该库。ECA 必须在真实关卡使用，不能只是保留旧源码。
- **取消：** 独立运行引擎、引擎适配层、强制纯 C#/引擎无关、自建世界模拟/独立时钟/表现快照同步、独立 .NET 宿主与双宿主一致性。
- **本轮不恢复：** 通用框架建设、全玩法 JSON、Schema/能力目录工具工程、第二内容包验证、框架冻结和旧 P1 流程。已有源码、算法、素材和证据保留；直接复用更快就保留，不为原生化强制重写。

## 系统职责与唯一状态

边界用直接组件引用、具体方法和必要接口表达；不建通用服务容器，不要求一个系统一个程序集。现有原生组件保留并纳入以下职责，不推倒重来。

| 系统 / 现有组件落点 | 职责与状态归属 |
| --- | --- |
| Entity / 场景实体组件 | 具体对象身份、存活与销毁；GameObject 生命周期即可，不另造世界模拟 |
| Map / 门与障碍组件 | 地图空间、碰撞、门开闭；只由 Map 修改通行状态，Physics2D 与现有空间算法按收益选用 |
| Actor / NativePlayer、NativeEnemy | 移动、生命与死亡状态；各实例持有自身数据，Unity 输入/刚体驱动 |
| Combat / 武器、NativeProjectile、Boss 攻击组件 | 开火开关、攻击冷却、索敌、伤害结算、击杀记录；通过 Actor 方法应用生命变化，不再复制生命状态 |
| Interaction / NativeInteraction 与候选选择组件 | 互动范围、候选、一次性消耗及有效互动事件；不直接包办目标和通关 |
| Quest / 目标组件 | 目标激活/完成、前置与替代完成；ECA 条件查询、Action 调用，UI 和 Level 不保存第二份任务状态 |
| Dialogue / 指挥官及对白组件 | 当前对白/主题/会话和一次性提示；实时通讯不暂停战斗 |
| Level / 收敛后的 NativeRunController | 局阶段、遭遇切换、胜败终态、启动和重开；不集中管理门、生命、目标、合同或全部叙事状态 |
| Narrative / 记忆与结局组件 | 记忆归属、同步/差异、本局行为记录和结局资格；ECA 调用具体记录方法，避免重复计分 |
| Support / 支援组件 | 合同状态与效果/授权提交；成功才提交代价，拒绝失败不扣费 |
| UI / PhoneUI、HUD、EndingController | 展示所属系统状态、路由输入；结局表现用协程，不成为业务状态副本 |
| ECA / 当前关卡规则组件或复用旧实现 | 只拥有规则绑定与执行进度；协调上述系统，不拥有生命/任务/门等业务数据 |

输入在明确组件集中采样，按职责分发；文本焦点屏蔽玩法输入，新确认才接受合同。Tab/E/Space 不沿用原型地图/背包/对话冲突。规则与参数可用 Inspector、Prefab、ScriptableObject、已有 JSON 或具体代码；不强制全玩法 JSON。

## 本关最小 ECA 调用关系

先评估已有 ECA 可用实现：直接调用更快就复用；若旧组装需引入 world/适配/双宿主链，则只补本关需要的 Unity 规则执行组件。事件有明确来源和所属关卡，Condition 只读，Action 调用业务系统方法；可用 Unity Update 处理必要事件队列、协程等待，不自造时钟或通用调度框架。当前只补使用到的顺序/等待/防重复与生命周期清理，不恢复整套并行、队列、钩子协议工程。

必须在 NativeDemo 正常操作路径接通：

1. 玩家靠近终端按 E → Interaction 发布有效互动事件。
2. ECA 条件读取 Quest：目标生效且未完成；读取 Level：仍在游戏中。
3. ECA 动作顺序调用 Quest 完成目标 → Map 开门 → Dialogue 显示下一目标对白。
4. 出口区域/互动事件 → ECA 查询 Quest 必需目标完成 → Level 提交通关；未完成则 Dialogue 提示。

后续 Boss/记忆/最终选择继续用少量 ECA 规则衔接；普通移动、物理、逐帧战斗在对应系统直接运行。重开由 Level 重载场景，各系统初始化自身状态；ECA 解除旧监听/结束协程，避免旧局继续执行。验收以真实操作触发这条规则链为准，不能只展示类名或闲置规则。

## 场景、资源与启动

新增独立 `Assets/Scenes/NativeDemo.unity`，尽量一个场景容纳入口、探索区、安全节点、Boss 区和结局 Canvas。根节点建议 Systems（Level、ECA、Quest、Dialogue 等）、World（Map）、Actors、UI；玩家、敌人、弹丸、互动点用具体 Prefab。必要时复用原型脚本，但避免旧全局自启动在新场景重复生成世界。

直接复用 Assets/CyberCity、Assets/Art/Generated 与现有角色/预警/UI 素材，保持 GUID；拖入 SpriteRenderer、Animator、AudioSource 和 Inspector 引用。不新建资源 ID 适配层，不删除历史场景。首次构建仅包含新入口及确实需要的场景。

启动：场景加载 → Awake 连接具体系统引用 → 各系统初始化自身状态 → ECA 绑定本关规则 → Level 开局、Quest 激活首目标 → Unity Update/FixedUpdate/协程驱动 → 互动/区域事件经 ECA 调用业务系统 → Boss 与最终节点 → 结局/死亡可重开。必要缺失引用直接显示可定位错误并修复，避免建设诊断框架。
