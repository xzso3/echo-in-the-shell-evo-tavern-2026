# 独立 Boss 关卡开发计划

编写日期：2026-09-21  
状态：2026-09-22 已完成首版实现与首轮场景验证；本文保留原设计基线，实际交付及差异见 [Boss 关卡实现与验证](Boss关卡实现与验证.md)。  
配套文档：[Boss 战美术资源需求](Boss战美术资源需求.md)。

## 1. 目标与设计边界

在现有赛博都市原型基础上新增独立 Boss 关卡，形成“战前拾取与整备 → Boss 战 → 途中获取补给 → 胜利或死亡 → 重试”的完整循环。

已确定的方向：

- 复用现有地面背景，缩小地图范围，集中走位压力。
- 不摆放具有碰撞体积的建筑、路障或其他场景物件；清除原街区内部障碍数据，只保留场地边界。
- 首版不生成普通小怪，避免自动索敌被干扰。
- 保留现有移动、自动攻击、背包换装与暂停操作，不增加冲刺、格挡或手动瞄准。
- Boss 使用锁定点射、定位轰炸、街道电网三个技能，分为两个阶段。
- 战斗过程中提供医疗和装备补给。

Boss 暂名 WARDEN-01（街区监管者）。以下尺寸、生命、伤害和时序均为首轮可调参数，不代表已验证的平衡结果。

## 2. 当前基础与复用范围

依据：[项目进度说明](项目进度说明.md)、[背包装备与掉落系统](背包装备与掉落系统.md)、[对话系统](对话系统.md)。

| 已有能力 | 本关卡使用方式 |
| --- | --- |
| 全向移动，基础速度 4.5 单位/秒 | 沿用；所有必躲攻击以裸装速度可躲为基线 |
| 自动选择 9 单位内最近可见敌人 | 将 Boss 接入相同攻击与伤害流程，不增加手动锁定 |
| 基础单发伤害 22，攻击间隔 0.48 秒 | 沿用装备计算和弹丸发射时的伤害快照 |
| 玩家 100 HP、受伤无敌 0.65 秒 | 沿用；Boss 各伤害来源共用玩家受伤保护 |
| 三栏装备、24 格背包、五档品质 | 复用装备定义、拾取与穿戴界面 |
| 装备吸附与掉落光柱 | 战前与战中装备使用同一套拾取行为 |
| 暂停、死亡、重开、基础 HUD | 扩展关卡状态，保持原有行为一致 |
| 现有赛博地面、玩家和弹丸素材 | 优先复用；新增资源详见美术需求 |

当前对话是测试入口，未接入剧情事件。本关卡不依赖对话推进，也不扩展任务或存档系统。独立场景应关闭 F 键测试对话入口，避免误触；原场景保留原行为。

## 3. 场景与场地

### 3.1 独立场景

- 建议场景：`Assets/Scenes/BossArena.unity`。
- 原 `CyberCity` 场景保留，不用修改原场景来替代独立关卡。
- 首版从编辑器直接进入 Boss 场景；从生存关卡传送、跨场景继承装备与生命暂不实现。
- 新场景创建独立场地配置，禁用普通刷怪，初始普通敌人数量为零。
- 不直接套用原城市的 115 处障碍矩形。没有摆放道具也不等于已经移除数据碰撞。
- 不运行会覆盖现有城市后续修改的初始构建器；新关卡需要独立的创建或配置入口。

### 3.2 场地布局

| 项目 | 初版目标 |
| --- | --- |
| 有效战斗区域 | 宽 18 × 高 12 单位，中心为局部坐标原点 |
| Boss | 位于中央；建议视觉直径约 2.5～3 单位 |
| 玩家起点 | 下方中央的整备位置，远离 Boss 与边界 |
| 补给位置 | 四侧中点附近，向内缩至少 1.5 单位；最终结合角色半径校验 |
| 场地边缘 | 清晰警戒线或能量围栏，与实际移动限制对齐 |
| 内部障碍 | 无 |
| 相机 | 固定构图，看清全场、预警与补给；为 HUD 留出空间 |

18×12 为灰盒起点，可比较 20×14 版本。依据实际视野、裸装可躲性和回到射程的时间选择，不为制造压迫而持续缩小场地。

Boss 主体是唯一需要单独处理的中央实体，不属于环境障碍。建议使用简单圆形阻挡，初始半径约 0.9 单位，并校验不会卡住玩家；不附加接触伤害。受击范围与阻挡范围分别配置，轮廓应清晰。若灰盒证实中央阻挡破坏走位，再调整半径。

### 3.3 地面与镜头

- 复用 `cyber_ground_64x44_32px.png`，保持现有 PPU 32 和原始像素比例。
- 从背景选择视觉干净的道路区域，通过 Sprite 子区域、遮罩或取景展示；不要把完整 64×44 地图直接压缩成 18×12。
- 地面自带的装饰只是视觉；若所选区域看起来像有不可通行物体，应更换取景区域。
- 场外部分通过边框或遮罩收口，不让玩家误判可通行范围。
- Boss 关卡禁用 Tab 的全城/跟随模式切换，固定竞技场镜头；原场景不受影响。
- 至少检查 16:9 和 16:10 显示比例，全场不能被血条或界面遮住。

## 4. 关卡流程

| 状态 | 行为 | 转换条件 |
| --- | --- | --- |
| 整备 | Boss 休眠，玩家可移动、拾取战前装备和打开背包；双方不攻击 | 玩家主动进入地面标出的启动区域 |
| 启动 | 显示 Boss 名称与短倒计时，约 2 秒；暂停伤害与自动攻击 | 倒计时结束 |
| 第一阶段 | 三个技能按易学习的顺序循环 | Boss HP 首次降至 50% 或以下 |
| 阶段转换 | 清除未结算危险，核心切换状态，短暂停顿约 2 秒，投放装备 | 转换结束 |
| 第二阶段 | 强化连击次数、改变电网方向，缩短招式间歇 | Boss 或玩家生命归零 |
| 胜利 | 停止所有攻击、清除危险与飞行弹丸、显示结果 | R 重开 |
| 失败 | 停止关卡模拟，关闭面板，显示死亡结果 | R 重开 |

整备区属于同一片开放场地，用地面标记表达，不添加内部墙体。玩家出生点不能与启动区域重叠；战斗开始后标记熄灭，外边界继续限制活动范围。

阶段转换开始时优先安全清场，不让上一招的轰炸或电网在转换期间突然结算。Boss 可在此短暂锁血，但首版不使用长时间无敌机制；过渡前的合法伤害不得回滚或补回。若伤害直接击杀 Boss，胜利优先于阶段转换。

暂停是覆盖在关卡状态上的行为：背包或手动暂停时，技能预警、弹丸、补给投放、倒计时和战斗计时全部冻结，关闭后从原进度继续。换装不能刷新攻击或技能冷却。

## 5. Boss 技能规格

统一流程：准备/预警 → 锁定 → 伤害生效 → 消退/恢复。预警只提示，不造成伤害；实际判定应由与显示范围相同的配置驱动。

### 5.1 锁定点射

- 炮口蓄能，显示朝向玩家的瞄准线；预警约 0.9 秒。
- 前 0.6 秒跟随玩家方向，最后 0.3 秒固定方向；锁定完成必须有形状或亮度变化。
- 发射一组 3 发脉冲弹，发射间隔约 0.15 秒，速度先试 6 单位/秒。
- 同一组弹丸沿锁定方向飞行，发射后不追踪；飞出场地后清理。
- 单次伤害初始 16；避免连续弹丸绕过玩家现有受伤无敌。
- 目的：教玩家横向移动，并通过锁定后的变向制造输出机会。

### 5.2 定位轰炸

- 在玩家当前所在位置创建固定圆形标记，半径初始 1.3 单位。
- 标记出现后不再追踪，约 1.1 秒后爆炸；圆心锁定、计时进度和爆炸边缘必须可辨认。
- 第一阶段连续标记 2 次，标记间隔约 0.65 秒；第二阶段改为 3 次。
- 每个标记只结算一次范围伤害，初始 20；爆炸视觉可短暂保留，但不得保留隐藏伤害。
- 预警超出边界时按实际场内范围显示和判定。
- 目的：促使玩家移动并规划折返，避免长时间站定输出。

### 5.3 街道电网

- 使用预先配置、经过检查的条带布局，不在首版随机铺满场地。
- 预警约 1.4 秒，通电约 1 秒，单次伤害初始 18。
- 第一阶段先用固定方向；第二阶段交替横向和纵向。
- 初始安全通道宽度建议不少于 2.5 单位，最终需要扣除玩家碰撞半径后检验。
- 对每次电网激活，同一玩家最多受伤一次；多个条带不能同帧叠加伤害。
- 目的：临时压缩空间，要求玩家提前选路，通电结束后释放场地。
- 禁止用中央 Boss 阻挡把安全通道切成无法进入的区域；不能要求玩家穿越电网才能脱困。

### 5.4 阶段与节奏

第一阶段建议顺序：点射 → 恢复约 1 秒 → 轰炸 → 恢复约 1 秒 → 电网 → 恢复约 1.5 秒。

第二阶段保留技能识别方式，轰炸增加一次、电网交替方向，恢复时间先缩短约 20%。先不缩短核心预警时间，不叠加不同技能的伤害阶段。同一技能内部的连续弹丸或轰炸允许重叠。

每轮技能开始前确保上一技能的有效伤害已结束。恢复期间 Boss 正常可受伤，让玩家有机会重新进入射程。

## 6. 物资补给

### 6.1 战前整备

- 正常出生时背包与装备栏仍为空。
- 在整备位置附近放置普通武器、普通鞋子、普通攻速配件各一件，全部使用真实拾取流程。
- 固定战前物资是独立 Boss 关卡的新规则，不修改原生存场景的随机掉落规则。
- 玩家可以不穿装备挑战；不要求任何移速装备才能躲招。

### 6.2 战中投放

| Boss 剩余生命 | 投放内容 | 目的 |
| --- | --- | --- |
| 首次到达 75% 或以下 | 医疗包 ×1，回复 25 HP | 给前半程一次修正失误的机会 |
| 首次到达 50% 或以下 | 稀有武器 ×1，配合阶段转换投放 | 提供明确的输出提升 |
| 首次到达 25% 或以下 | 医疗包 ×1，回复 25 HP | 支持最后阶段继续挑战 |

- 每个节点每局只触发一次，不按时间无限补给。
- 一次伤害跨越多个阈值时，将尚未触发的投放加入队列，依次处理，不遗漏或重复；Boss 已死亡则取消未完成的投放。
- 优先选择场内、距离边界足够远且未被物资占用的投放点。投放不能与有效危险区域重叠；必要时延后到技能恢复期间。
- 投放前显示约 0.8 秒中性落点标记，与敌方轰炸预警形状明显不同。
- 物资落地不造成伤害、不阻挡移动，不能生成在玩家无法到达的位置。
- 医疗包建议 0.8 单位范围直接拾取，不占背包；满血时不消耗，恢复不超过最大生命。
- 装备沿用现有 2.8 单位吸附与背包流程；满包时留在地上并提示，玩家可暂停整理。
- 医疗包与装备保留至拾取或本局结束，不新增过期压力。

## 7. 数值与平衡基线

Boss 初始生命建议 2600，固定生命，不随玩家装备或战斗时长补偿增长。

| 装备组合 | 理论持续命中 DPS | 对 2600 HP 的理论时间 |
| --- | --- | --- |
| 裸装 | 22 / 0.48 ≈ 45.8 | 约 57 秒 |
| 普通武器、普通配件 | 32 × 1.15 / 0.48 ≈ 76.7 | 约 34 秒 |
| 稀有武器、稀有配件 | 42 × 1.25 / 0.48 ≈ 109.4 | 约 24 秒 |
| 传说武器、传说配件 | 82 × 1.60 / 0.48 ≈ 273.3 | 约 10 秒 |

以上不包含走位、脱离射程、发射与命中时差、阶段暂停，不是实际战斗时长。战中只投稀有武器，不能按“稀有武器＋稀有配件”估计全部玩家的后半程输出。

首轮目标：使用本关提供的装备，完整战斗约 45～75 秒；裸装可通过但耗时更长。高品质装备允许明显缩短战斗，不增加强制阶段锁血来拖长所有玩家的时长。

重点记录：战斗时长、实际受伤次数、各技能命中次数、输出时间占比、补给拾取率、角落受困情况。先调整安全通道与预警，再调整伤害和生命。

## 8. 开发任务与顺序

| 阶段 | 主要任务 | 完成条件 |
| --- | --- | --- |
| P0：代码接入检查与灰盒 | 阅读现有伤害/索敌/暂停流程；创建独立场景与配置；移除内部障碍；设置镜头、边界与占位 Boss | 场地可完整绕行，原场景行为不变，自动攻击可命中并击败占位 Boss |
| P1：单技能循环 | 依次实现点射、轰炸、电网；每个技能可独立调试；接入统一伤害保护 | 裸装能通过读预警躲开每个技能，无视觉与伤害范围错位 |
| P2：两阶段与流程 | 接入整备、启动、阶段转换、胜败、血条、重开 | 能从空背包开始完整打完一局并重复开始 |
| P3：补给 | 战前装备、阈值投放、医疗拾取、满血/满包处理 | 阈值不重复，补给可到达，暂停与重开不残留物资或定时任务 |
| P4：美术接入 | 接入 Boss、预警、电网、医疗包、边界与血条；维持灰盒判定 | 像素清晰、攻击可读、补给与危险标记不混淆 |
| P5：试玩与调参 | 完成专项验证，实际键鼠试玩，记录并调整难度 | 下节验收通过，更新进度文档与已知问题 |

先完成可玩的灰盒，再制作或接入正式美术。每个阶段完成后才进入依赖它的阶段；不把尚未验证的数值写成最终标准。

建议新增独立的关卡控制、Boss 行为和补给职责模块，例如 `BossEncounterController`、`WardenBossController`、`BossSupplyController`，以配置资产保存调参项。名称与具体拆分在阅读代码后确定，避免继续把全部新逻辑堆进 `PlagueGame.cs`，也不进行与本任务无关的全项目重构。

## 9. 验收清单

### 玩法与公平性

- 裸装速度下，场地中心、四侧、四角均有机会离开每种攻击；预警出现时已处于危险区也要有合理反应余量。
- Boss 中央阻挡、边界与安全通道组合不会产生无解位置。
- 自动攻击在射程内正常命中，场地边缘脱离射程有明确反馈或可通过走位理解。
- 第一阶段能观察到三种技能；第二阶段变化清楚，但预警语义一致。
- 不出现出屏攻击、永久封路、无预警伤害或同帧多段异常扣血。

### 系统与状态

- 暂停与背包冻结全部战斗计时；关闭后延续进度，不补发一批弹丸。
- 医疗不超过最大生命，满血不消耗；满包保留装备。
- 跨多个血量阈值只产生对应的有限补给，暂停或换装不能重复触发。
- 死亡或胜利时清除待爆标记、电网、弹丸和未完成投放；同帧胜败规则明确且稳定，建议玩家死亡优先。
- R 清除 Boss、危险物、补给、背包、面板与所有阶段标记，恢复初始整备状态。
- 原生存场景的刷怪、镜头、装备和对话操作保持既有行为。

### 画面与试玩

- 16:9 与 16:10 下全场、血条和补给点可见；E 面板和胜败界面无遮挡错误。
- 真实键鼠验证移动、拾取、E、ESC、R，以及 Boss 场景中 Tab/F 的禁用行为。
- 编辑器编译无错误，完整胜利和失败流程均实际跑通；重复重开无重复 Boss 或旧危险物残留。
- 保存关键截图与测试记录。独立程序打包不属于本阶段默认验收，未做时明确记录。

## 10. 首版暂不包含

普通小怪增援、可破坏建筑、动态障碍、精确弱点瞄准、多 Boss、随机技能池、冲刺/翻滚、装备新词条、跨场景成长、主菜单、存档、完整剧情、完整音乐音效与正式逐帧角色动画。

这些内容并非首版 Boss 成立的前提。后续以试玩结果和新的开发需求决定是否加入。
