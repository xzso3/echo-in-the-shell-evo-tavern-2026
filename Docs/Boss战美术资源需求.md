# 独立 Boss 关卡美术资源需求

编写日期：2026-09-21  
状态：2026-09-22 已接入现有 BossArena 成品资源与 P0 程序预警；本文保留需求规范，实际接入及截图见 [Boss 关卡实现与验证](Boss关卡实现与验证.md)。  
玩法与时序依据：[Boss 战开发计划](Boss战开发计划.md)。

## 1. 美术目标

沿用现有 Neural Lockdown 的赛博都市像素风，在小型、无内部环境障碍的竞技场中，让玩家一眼分清 Boss、危险预警、安全空间与补给。

Boss 暂名 WARDEN-01（街区监管者），采用固定部署的安保机甲/炮台造型：宽阔底座、清晰炮口、可见能源核心。第一阶段表现正常安保系统，第二阶段表现核心过载。通过发光部件、炮口姿态和程序位移表现动作，不依赖完整行走动画。

优先级说明：P0 为首版必需的视觉功能，可先用程序图形或占位图验证；P1 为玩法成立后的表现增强。本轮不要求图中所有状态都制作成独立逐帧动画。

## 4. Boss 绘制要求

### 4.1 造型与尺寸

- 采用与现有俯视场景一致的观察角度，不制作横版侧视 Boss。
- 主体使用同一 128×128 画布，画布按 PPU 32 对应 4×4 单位；可见机身约占 80～96 像素，形成约 2.5～3 单位的视觉体量，其余空间保留给炮口与发光。
- 装甲底座、炮口、核心在游戏实际显示尺寸下可识别，不依赖微小文字或密集线路。
- 固定底座强调“部署设备”，炮口指向清楚，核心能明显切换阶段状态。
- 炮口旋转采用平面转向时，要控制透视，避免画成只能面向单一角度的强侧视形态；若需要方向帧，在灰盒验证后单独追加。

### 4.2 分层与锚点

- 各层使用相同画布、共同中心 Pivot；不得分别自动裁紧后丢失对齐关系。
- 标明炮口挂点、核心中心、视觉底座中心，坐标记录在资源说明中。
- 核心发光单独导出蒙版，供程序实现第一阶段青色、第二阶段橙红色及蓄能变化。
- 受击闪白、轻微后坐、蓄力脉冲、阶段闪动可由程序实现。
- 碰撞、受击框、挂点辅助线只出现在说明图，不烘焙进游戏贴图。

## 5. 战斗信息的视觉规则

| 信息 | 建议颜色与形状 | 必须表达的区别 |
| --- | --- | --- |
| 正在蓄力/即将伤害 | 琥珀或橙色，虚线/斜纹/未闭合轮廓 | 玩家仍有反应时间 |
| 已锁定位置 | 更亮的完整轮廓，方向箭头或端点变化 | 目标不再跟随玩家 |
| 伤害生效 | 红橙或高亮电弧，短促闪动 | 与单纯预警有明显状态差异 |
| 安全通道 | 尽量保留原地面，可配低强度边缘提示 | 不被电网特效覆盖，不依靠绿色涂满地面 |
| 医疗包 | 绿色主体、浅色医疗符号 | 即使不辨颜色也能认出用途 |
| 装备补给 | 沿用现有品质颜色与装备图标 | 不把品质光柱误认成危险预警 |
| 补给投放 | 方形四角标记与物资图标 | 不能和轰炸圆圈使用同一套形状 |

- 提示不能只依赖红绿差异，同时使用形状、边框和状态动画。
- 技能范围由配置驱动，贴图按真实范围显示。发光外晕只作装饰，不得误导有效伤害边界。
- 轰炸预警初始半径 1.3 单位，在 PPU 32 的资源尺度下，直径约 83 像素；128×128 画布需要预留透明边距，接入时以世界尺寸和有效圆环边界校准。
- 电网纹理沿长度平铺，不将像素纹理极端拉伸；安全通道需要清晰完整。
- 视觉覆盖顺序需兼顾角色与预警：地面最低，预警高于地面；角色始终可辨，危险范围不被物资光柱完全遮住，HUD 最上层。具体 Sorting Layer 在接入时确定。
- 不使用持续全屏闪光或大面积浓烟遮住下一招提示。

## 6. 文件与导入规范

建议源资源目录：`Assets/Art/Generated/Cyberpunk/BossArena/`。建议游戏派生 Sprite、配置、预制体分别存放于独立的 BossArena 目录，避免覆盖当前城市场景资产。

| 项目 | 规范 |
| --- | --- |
| 文件格式 | PNG RGBA，真正透明背景；不得烘焙棋盘格或纯色底 |
| 像素采样 | Point；关闭 mipmap；不使用有损压缩 |
| 世界贴图 PPU | 默认 32；特殊效果如需不同值必须在说明中记录 |
| 图集 | 规则网格，每帧等尺寸，写明行列、帧序、帧率建议和循环方式 |
| 图集留边 | 明确统一单元格尺寸和透明边距；如打包时需要 padding，由打包设置处理 |
| Pivot | Boss 各层统一中心；其他资源默认中心，例外须说明 |
| UI | 依据 Canvas 实际尺寸导入；边框使用九宫格或程序布局，不沿用世界尺寸推断 |
| 命名 | 小写英文下划线，如 `warden_body.png`、`warden_core_mask.png`、`supply_medkit.png` |
| 文字 | 名称、伤害数值、倒计时、阶段提示由 UI 绘制，不烘焙进贴图 |

生成图或绘制母图不能直接等同于成品 Sprite。需要清理透明边缘、确认网格与层间对齐，避免重复现有母图底色残留问题。源文件与实际引用成品分开命名保存。

## 7. 交付顺序

1. 灰盒阶段：程序圆形/矩形、现有弹丸、装备图标和简单医疗占位。先确定场地与伤害范围。
2. 可读性阶段：优先完成 B01、T01～T04、S01～S02 与边界。验证实际游戏尺寸下的辨识度。
3. 表现阶段：接入爆炸帧、Boss 阶段损伤、残骸与辅助特效。
4. 整体验收：在正式背景上截图和实际移动试玩，检查预警与背景、物资光柱、Boss 外晕是否互相干扰。

每组资源应同时提供：独立 PNG/图集、资源说明、透明背景预览、放到实际竞技场背景上的比例预览。图集附帧编号，Boss 附挂点坐标。

## 8. 美术验收

- 实际镜头下能区分玩家、Boss 炮口、补给、预警和伤害生效状态。
- 贴图无不透明底色残留、无烘焙棋盘格、无因缩放产生的模糊边缘。
- 动画或分层切换不出现位置跳动，炮口与弹丸出生位置一致。
- 地面与边界不存在“看起来可走却不能走”或“看起来有墙却能穿过”的矛盾。
- 医疗包不与地面装饰混淆；投放标记不与敌方轰炸混淆。
- 所有攻击视觉与灰盒判定校准后再替换，不因美术换图偷偷扩大伤害范围。
- 16:9、16:10 下血条、补给提示和场地无遮挡，背包与胜败界面保持可用。

## 9. 本轮不制作

新城市地面母图、内部建筑与碰撞道具、普通小怪、Boss 行走/追逐动画、新玩家动作、剧情立绘、新装备类型图标、全套主菜单、完整音乐与音效包。必要的视觉反馈优先通过本清单中的可复用素材和程序表现完成。
