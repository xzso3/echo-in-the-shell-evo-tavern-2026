## 1. 目标与阶段边界

一份 ContentPackage 经校验后，能在新 framework 中运行小关卡；冻结框架后，第二份内容包仅通过配置与资源改变布局、敌人参数、对话和目标组合，仍能通过相同验收流程。

| 要求 | 第一阶段交付 |
| --- | --- |
| R01 分层 | Core、Gameplay、Unity Host、Tooling 的依赖可检查 |
| R02 内容生产 | 版本化内容包、能力目录、Schema、资源引用和诊断报告 |
| R03 ECA | 事件、纯条件、即时及持续动作、作用域、取消和追踪 |
| R04 空间 | 四个 Chunk、连接端口、统一阻挡、动态门、可达性 |
| R05 角色战斗 | 玩家移动及自动攻击、一种敌人、基础感知和攻击流程 |

## 3. 四层依赖与建议目录

```text
Assets/EchoFramework/
  Core/                  # Echo.Framework.Core
  Gameplay/              # Echo.Gameplay
  UnityHost/             # Echo.UnityHost
  Editor/                # 资源导入、构建接入；不制作编辑器产品
  Tests/                 # Unity 接入和表现验证
  Samples/               # 验证场景及宿主入口
ContentPackages/         # 原始内容包，配置和资源是内容事实来源
Tools/EchoContent/       # 目录导出、校验与无图形用例入口
Tests/EchoFramework/     # 纯逻辑用例与验收夹具
```

Core 不引用 UnityEngine、UnityEditor、Gameplay 或具体内容。Gameplay 依赖 Core，管理自身状态；空间计算可用纯 C# 实现。Unity Host 组装模块并提供输入、资源和表现适配。Tooling 使用同一注册器、加载器及逻辑模块；Editor 适配独立隔离。

逻辑源码在 Unity 与外部测试宿主间共用，禁止维护两套行为实现。程序集和外部项目的目标框架、语言版本、JSON/Schema 库由 P1-01 在现有 Unity 上做最小兼容检查后锁定，记录许可证与版本；本阶段不以升级 Unity 为前提。

启动先完成内容和资源预检，再创建作用域、模块实例及监听，随后发布 level.started 并完成首轮任务激活，最后开放玩家输入。启动失败需清理本次已创建对象并返回诊断，不能留下可操作的半加载世界。

建议接口职责如下，签名在 P1-01 冻结：

| 接口角色 | 输入与输出 |
| --- | --- |
| 模块注册 | 注册内容类型、状态查询、命令、事件、条件、动作与钩子 |
| 内容解析 | 解析类型化 ID，返回已校验只读定义；无法解析返回定位错误 |
| 逻辑世界 | 接收标准输入意图，按逻辑步推进，输出事实与只读表现快照 |
| 动作实例 | 开始、推进、取消，返回 running/succeeded/failed/cancelled |
| 空间查询 | 位置、形状、通行类别，返回碰撞、视线或路径结果 |
| 表现接入 | 接收实体、动画阶段、对话会话及界面状态，提交用户意图 |
| 执行追踪 | 记录规则、实例、来源、原因、逻辑步与状态变化 |

## 4. 内容包与引用契约

包清单最小字段：`package_id`、`package_version`、`schema_version`、`required_capabilities`、`dependencies`、`exports`、`entrypoints`、资源清单引用。依赖记录精确版本与内容摘要；加载前检查重复、循环、缺失和能力兼容。

建议内容 ID 格式为 `package_id:type/local_id`，例如 `p1.sample_a:level/main`。内容 ID 与运行实例 ID 分开；同一 ChunkDefinition 或 ActorDefinition 可创建多个实例。区域和标记引用携带 Map/Chunk 实例上下文，不能只靠重名的局部标记定位。

引用跨包内容时必须声明依赖，并引用其导出项。Unity 资源定位由导入清单映射稳定资源 ID，不使用场景层级路径或 GameObject InstanceID 作为内容身份。

各类 JSON 的必填字段、类型、枚举、默认值、范围和示例由同一注册描述生成 Schema 与能力目录。未知字段、未知能力、错误引用类型和不支持的版本均显式诊断；内容中不运行 C#、任意表达式或任意脚本。

源包与 Unity 导入产物分开，导入应可重复生成。报告不参与源内容摘要，避免报告改变包摘要；摘要覆盖清单、定义、规则、资源与声明式用例，并记录依赖摘要和框架版本。

## 5. ECA 第一阶段执行语义

### 5.1 规则、状态与上下文

规则最小包含稳定 ID、绑定范围、事件匹配、条件、动作树和重复触发策略。只读 RuleDefinition、持有冷却/次数的 RuleSetInstance、单次 ExecutionInstance 分离。条件复用 `all/any/not`，不得改变任何状态。

基础值支持布尔、整数、有限浮点、字符串及类型化 ID；枚举由字段规范约束。变量声明类型、默认值和 run/level/encounter/entity/execution 作用域。实例引用必须检查类型和存活性；引用失效不能重新绑定到恰好同名的新实例。

事件载荷在提交时固定。条件中的模块查询读取处理时状态，动作执行时再次检查必要条件。来源快照和当前查询明确区分。内容仅能发送其声明的自定义事件，战斗命中、交互成功等权威事实由所属模块产生。

### 5.2 时间与事件调度

建议逻辑步为可配置的固定步长；样例基线采用 1/60 秒。输入采样与画面插值由宿主承担。无图形用例直接提供相同的输入意图和逻辑步，固定随机种子；现阶段样例尽量采用确定生成与选敌。

每步顺序固定：接收输入意图 → 推进所属模块和到期动作 → 处理事实队列与就绪 ECA → 发布表现快照及追踪。模块顺序在启动时确定；事件以入队序号处理，同一事件的规则按优先级、规则 ID、绑定实例 ID 排序。新事实入队，不同步递归派发。

动作等待使用明确时钟；模拟暂停时逻辑等待不前进。对话会话仍能接收结束/选择意图。零时长等待至少让出到下一逻辑步。配置事件处理预算，超限须产生因果链诊断并将该验证场景判为失败，不静默丢失事件或报告成功。

### 5.3 组合、重入与取消

顺序在上一动作成功后继续；并行默认等待全部成功；有限重复次数必须有界；事件等待绑定范围、过滤条件及超时，首次匹配后解除监听。事件等待默认面向订阅后的事实，任务历史追认通过任务模块完成。

重入提供 ignore/restart/queue/parallel。queue 与 parallel 必须有容量上限，超额拒绝新触发并记录原因；队列开始执行前用保留的事件载荷重新查询当前条件。restart 先完成旧执行清理再启动新实例。

动作失败停止当前流程；并行子动作失败时取消其他仍运行分支，待清理完成后报告失败。取消必须幂等，并清理等待器、监听和临时控制占用；已提交的伤害与交互结果保留。首阶段动作的清理必须有界，无法完成时报告错误，不能无期限等待。

### 5.4 同步钩子

第一阶段提供伤害提交前钩子。仅允许注册为该阶段合法的即时操作修改候选伤害，不开放任意状态写入。钩子按优先级及稳定 ID 排序，战斗模块最后校验并统一提交；钩子异常使本次候选结算失败并留下诊断，不提交部分结果。

等待、并行、持续动作和递归派发不能进入同步钩子。具体能力见能力清单。

## 6. 样例所需领域协议

| 类型 | 最小数据 |
| --- | --- |
| Tile/静态物件 | 外观引用、地形或占地、movement/projectile/sight 三类阻挡 |
| Chunk | N、地形网格、装饰、物件、命名标记、边界端口 |
| Map | Tile 世界尺寸、Chunk 实例、位置、端口连接和区域 |
| Actor | 阵营、体积、移动参数、生命与攻击参数、能力、控制及表现引用 |
| Attack/Projectile | 目标方式、阶段流程、冷却、挂点、伤害、速度、寿命、碰撞与来源信息 |
| Level/Encounter | 地图、入口、实体及敌人布置、区域、任务、规则和结果条件 |
| Interaction/Door | 范围、视线要求、可用条件、一次性策略、门状态与阻挡贡献 |
| Quest/Objective | 激活条件、目标、all/any 与前置依赖、来源过滤、完成条件 |
| Dialogue | 稳定节点 ID、说话者、文本、条件、选项或下一节点 |
| Animation/Presentation | 帧、时长、朝向、基准点、挂点、语义动作和阶段映射 |

### 6.1 地图和坐标

样例 A 建议 N=16、Tile 世界尺寸=1，均为内容参数。逻辑坐标使用二维 XY，Tile 局部原点为左下，数组索引 `y*N+x`；Tile 中心为 `(x+0.5,y+0.5)`。Chunk 以整数区块坐标摆放，第一阶段不支持旋转或镜像装配，相关配置须明确拒绝。

物件用轴对齐矩形阻挡，角色体积使用圆半径；运动和弹丸采用覆盖完整位移的查询以防穿透。寻路与视线使用同一阻挡来源，动态门状态改变后使相关查询数据失效并更新。跨 Chunk 物件由一个放置实例拥有，其世界占地参与所有涉及区块的查询。

端口沿边界使用半开区间 `[start,end)`，类型与位置匹配，实际通行和角色体积仍需验证。分别检查门关闭和打开时的必需路径，检测未声明的跨区块通路。地图与显示重建不生成新的领域实体身份。

### 6.2 角色与攻击

玩家以 WASD 移动，初始自动开火，Space 切换；E 交互。自动选敌检查敌对阵营、射程和视线。敌人用当前感知选择目标，通过 ECA 切换待机/追击/攻击；追击和攻击由持续能力执行，丢失目标时遵守配置的可见性规则。

首阶段实现一种直线弹丸攻击。开始攻击时创建独立执行实例并检查冷却与状态；冷却建议从成功开始时起算，取消不返还已消耗冷却。发射时固定本次弹丸伤害与来源，弹丸归属关卡作用域，已发射弹丸在攻击结束或攻击者死亡后按该策略继续存在，关卡结束时清理。取消阻止尚未发生的发射。

动画使用同一阶段进度，挂点由逻辑配置计算；隐藏显示对象不改变命中时刻。普通死亡先取消角色控制与未完成攻击，提交死亡事实，再由仍有效的规则处理后续，最终移除实例。此阶段不实现随机掉落。

### 6.3 交互、任务和对话

交互在确认时检查对象、距离、视线和忙碌状态，并产生带唯一交互结果 ID 的事实；一次性终端只提交一次成功。一次成功可触发开门、对话与任务进度，但各模块分别管理自身状态。

任务跟踪器消费所属模块产生的事实，按来源对象与结果 ID 去重。样例目标为 interaction 与 reach_region，支持 all/any 和前置依赖；不依靠内容直接设置 completed。进入出口时重查必需目标，任务与关卡完成各提交一次。

短对话通过独立会话运行，显示由宿主适配。默认样例采用非暂停式短对话；选择和推进走输入命令并重查会话。完成返回 succeeded，中断返回 cancelled；开启对话的 E 输入不能继续用于推进该对话。

## 7. 样例 A 与内容变体 B

样例 A 使用四个 Chunk 实例组成 2×2 地图：入口区、战斗通道、绕行通道、终端出口区。主路径经过敌人，绕行路径提供实际可通行的替代路线；终端打开通往出口的门。一个玩家、一种敌人、一个终端、一扇门、一个任务和一段对话构成基础内容。

绕行只用于验证替代路线，本阶段不据此宣称已经实现正式避战计分。验收夹具可增加同定义敌人实例，验证作用域隔离。

变体 B 在同一能力集上更换布局、敌人参数和对话，并将任务配置为两个终端全部完成后开放出口，以验证目标组合与内容复用。每条交战和绕行路线都需覆盖相应目标。测试内容不属于正式关卡或正式角色设定。

开门规则响应终端目标进度变化，只检查所需终端目标；到达出口是后续完成目标。禁止把包含抵达出口条件的整个任务完成作为开门前提，否则形成目标依赖死锁。

样例使用声明式内容表达差异。运行代码不能按包 ID、关卡名或特定终端 ID 分支。依赖共用素材时精确声明包与版本；素材不足可用明确标记的测试图形验证，最终表现验收必须记录资源质量和动画覆盖情况。

至少提供一套能够区分前摇和发射姿态的多帧测试动画，验证阶段与表现映射；占位素材必须标注，不能把所有动作绑定为同一静态帧后声称动画时序已验证。
