# P2 聚焦验收清单

状态区分为 `not_run`、`passed_editor`、`passed_windows`、`failed`。执行任务的 Play 检查与用户的 Windows 人工试玩分开记录，不互相替代。验收只覆盖本轮改动和受影响主线。

| ID | 检查 | 证据要求 | 当前 |
| --- | --- | --- | --- |
| A1 | 打开 `NativeDemo`、Unity 编译，NPC 和按钮/文本资源无缺失 | 执行者报告 Unity 版本、退出状态与资源检查 | not_run |
| A2 | 靠近 NPC 按 E 才能对话；离开范围不能隔空提交；新选择不由开对话的 E 自动触发 | 聚焦 Play 操作与结果 | not_run |
| A3 | 私人记忆分支：选择、实际找回记忆、返回 NPC 完成；若先找回再选择也能正确处理 | 聚焦 Play 操作与 Quest 状态 | not_run |
| A4 | 检修通道分支：选择、实际穿过通道、返回 NPC 完成；若先绕行再选择也能正确处理 | 聚焦 Play 操作与 Quest 状态 | not_run |
| A5 | 两分支互斥，重复选择/互动不重复结算；任务、对话和手机/HUD 的可见状态一致 | 执行者报告可见反馈与所属状态 | not_run |
| A6 | 原三记忆→relay→Boss 核心 E→最终节点可继续；四结局阈值和支援代价未改 | 受影响路径冒烟和差量检查，未走过的路径标未测 | not_run |
| A7 | 交付工作区的集成提交、入口场景、字体与唯一构建场景明确 | INT-00 报告 SHA、范围及交接说明 | not_run |
| A8 | Windows 人工靠近 NPC、完成实际选择的一条分支，原主线仍可继续 | 用户说明版本、路径和现象；未玩的另一分支仍标未测 | not_run |

严重程度优先级：编译/启动失败、流程卡死、错误自动提交或输入冲突、缺失关键资源先修。非阻断的小问题记录后由用户筛选。本阶段不建设自动化测试体系，不重跑旧 G1/G2/G3 或全部四象限。

通过 A1—A7 表示可交用户 Windows 构建的源码已完成；A8 是实际平台验收。状态台账记录每项对应提交和证据，不能把脚本定位、编辑器状态注入或旧版 Windows 结果描述为完整人工通关。
