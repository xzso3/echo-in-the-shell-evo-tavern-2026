## P2-01 任务卡

- 输入：`c8083c1`、现有 NativeDemo、当前 `NativeQuest`、`NativeNarrative`、`NativeDialogue`、`NativeInteraction`、`NativeEcaRules` 及 FusionPixel。
- 工作：在现有场景接入一名 NPC；显示两条互斥可选分支；从真实私人记忆或检修通道事实推进并返回 NPC 提交；用 ECA 协调事件、条件和动作。业务状态按实现规范归属。
- 输出：新 `codex/` 分支及提交、可直接打开的场景、简体中文操作说明、实际检查和未测项。原工作区分支与产物保留。
- 边界：不改结局计分、支援授权、Boss 判定或原主线规则；不制作第二关、通用框架工具或 Windows 构建。
- 验收：开发期只做 [验收清单](PHASE2_ACCEPTANCE.md)中必要的编译/启动/当前阻断检查；其余由用户最后人工试玩。

## P2-02 任务卡

- 只从 P2-01 的新分支选择本轮提交；核对与最新集成基线的差量、场景引用、中文字体和 Build Settings 唯一启用场景。
- 如有冲突或实现缺口，交回 P2-01 修补；不替执行任务重做功能。
- 不混入旧 P1 分支祖先链，不删除历史素材、工作树和 `Tests/Tools` 旧 `bin/obj`。
- 回报新交付工作区 SHA、实际集成检查、人工未测项及面向用户的打开/操作说明。

## P2-03—P2-09 任务卡

每项具体最小交付见 [优先队列](PHASE2_ROADMAP.md)。派发前主控核对当时集成 SHA、前置接口、负责文件及 Unity 槽；将该项的目标、修改边界、必要检查和未测项写进完整派发消息。执行者在自己的新 `codex/` 分支保留旧成果，提交可集成的最小切片，不重建已完成内容。INT-00 在每个切片后只导入本轮提交、更新交付说明，不重复全量验证。

- P2-03 先扩可走地图，保持原 NativeDemo 主线和场景入口。
- P2-04 的 Actor/Combat 代码与预制体可与地图工作并行，但不得同时控制 Unity Editor 或写共享场景。
- P2-05 可并行准备道具/装备/移动效果代码与资源，不改 P2-04 的敌人或 Combat 文件；随后接线，以可实际拾取/装备/生效为门槛，避免只写抽象接口。
- P2-06 可并行制作有许可记录的音频资源及管理组件，不写共享场景；随后占用空闲 Unity 槽接线，必须有可听结果，不能只添加空 AudioSource。
- P2-07 只从真实重复中提取，保持 ECA 编排和系统状态归属。
- P2-08、P2-09 在截止前若条件或时间不足，保留需求与已做分支，不伪称已实现。在线指挥官的外部服务/凭据缺失不能以伪联网演示代替。

## 续派规则

同一工作包的修补继续原任务；独立、文件边界明确的工作可并行。任何时候最多 **5 项执行任务**，Unity Editor 同时只归一项；INT 集成/收束占一个执行槽。主控只负责文档、调度、核查与验收。用户本轮结束后的暂停要求优先于常规续派规则；再次授权恢复后，下一项在前置提交和证据到位时直接派发。派发或续派统一指定 `gpt-6-sol`、`xhigh`。

新功能按用户确认的 P2 优先级推进；只有完成当前切片并出现可集成基线，才派后续依赖任务。08:00 后停止新增功能，11:00 如实移交未完成项。历史 P1 列表不会自动增加工作。
