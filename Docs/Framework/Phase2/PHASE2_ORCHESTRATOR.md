# P2 主控执行规则

主控依本文件持续调度 [P2 任务](PHASE2_TASKS.md)，直到当前阶段完成、发生必须由用户处理的外部阻断，或用户明确更改目标。此处“持续”指当前及后续接续运行的调度，不承诺应用关闭后自动运行；中断后按 [状态台账](PHASE2_STATUS.md)和任务记录恢复。

1. 每次恢复先读 [状态台账](PHASE2_STATUS.md)、[任务卡](PHASE2_TASKS.md)、[验收清单](PHASE2_ACCEPTANCE.md)，再核对交付工作区的 HEAD、集成引用、未提交变更和当前执行任务状态。已有有效提交和检查不重做。
2. 主控只写阶段文档、派发与验收；代码、场景、Unity 操作及 Git 集成交给执行任务。优先复用 P1-07、INT-00、P1-06、P1-05 的现有任务，历史名称不代表恢复旧 P1。最多两个执行任务并发，Unity Editor 同时只归一项。
3. 新任务从当时的 `codex/unity-native-integration` 精确 SHA 起步，保留已有分支和用户改动。执行者只交付本轮新提交；集成任务只选择这些提交，不导入旧 P1 祖先。
4. 用户指定所有后续任务使用 GPT-6 Sol、Extra High；派发工具中明确使用 `model: gpt-6-sol` 与 `thinking: xhigh`。运行中无法原地换模型的回合，以后续同设置回合接续，不丢弃其工作。
5. P2-01 完成后读取执行者提交、文件差量和实际检查范围；编译/启动或当前流程阻断交还原任务修。不要等 A2—A6 全部开发期通过才集成；A1 无阻断、未测项写明，即派 INT-00 执行 P2-02，核对新 SHA、唯一构建场景和交付说明，再由用户自行 Windows 构建。
6. 用户反馈只按实际跑过的路径记录。严重问题派原任务修复，INT-00 再集成；必要时只复验受影响路径。未测项目保持 `not_run`，不扩大旧 Windows 结论。
7. 每次交付、返修或基线变化更新状态台账：任务 ID、状态、分支/SHA、实际检查、未测项、下一依赖。用户主控工作区已有未提交文档改动和交付工作区旧 `bin/obj` 保留，不顺手暂存、重置或清理。
8. 用户已确认 [优先队列](PHASE2_ROADMAP.md)：Chunk/Map → Actor/Combat → 道具/装备/Buff → 音效/BGM → ECA 复用 → 记忆/叙事/支援 → 在线指挥官优先。参考 `UNITY_NATIVE_PLAN.md` 的快速执行策略，功能优先，必要检查后尽早交人工试玩；有稳定新集成点就按依赖续派。
9. P2 于 2026-09-24 08:00 停止启动新功能，08:00—11:00 只做用户 Windows 人工试玩及严重问题修复；11:00 收束。未完成项保留分支、源码和证据，另开后续阶段，不冒称 P2 完成全部七组目标。

P2-01 已交付，P2-02 正集成。取得新集成 SHA 后，按用户顺序启动 P2-03，文件边界允许时并行 P2-04；不得为填满并发槽而启动无依赖价值的框架工作。
