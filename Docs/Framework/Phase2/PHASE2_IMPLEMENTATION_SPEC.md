- 截止仍按 2026-09-24 11:00（UTC+8）；用户自行进行 Windows 构建和试玩。

## 2. 玩家路径

1. 玩家靠近 NPC 按 E，对话给出两个明确选项：“提交私人记忆记录”和“提交检修通道报告”。名称可按文案润色，但条件必须对应真实事实。
2. 选择一项后，Quest 记录唯一分支并显示当前目标；另一项锁定。已在选择前取得的私人记忆或已走过的通道应被正确识别。
3. 私人记忆分支只在 Narrative 确认已找回私人记忆后可提交；路线分支只在 Narrative 确认玩家实际穿过检修通道后可提交。
4. 返回 NPC 再按 E 提交；成功仅结算一次，给出分支各异的对话结果。重复互动只显示已完成结果，不重复记账。
5. 无论是否接支线，原三记忆 → relay → Boss 核心 E → 最终节点仍可继续。

这是可选的局内分支，不改变现有同步度、差异度、支援代价或四结局阈值。NPC 内容应明确是本地固定角色，不冒充在线 AI 或真实前代玩家。

## 3. 状态和 ECA 边界

| 组件职责 | 本阶段归属 |
| --- | --- |
| NPC / Actor | 身份、存在与可交互表现；不保存任务或叙事分数的副本 |
| Interaction | 距离、候选与有效 E 互动事件；交互发生时重新检查可达性 |
| Dialogue | 会话文本、两个可选项的呈现与选择事件；不直接改任务 |
| Quest | 分支选择、当前目标与完成状态；确保互斥和一次性完成 |
| Narrative | 已取得的私人记忆和实际绕行事实；本阶段只读查询 |
| ECA | 监听 NPC 互动与选项事件，读取 Level/Quest/Narrative 条件，再调用所属模块提交和反馈 |
| Level / UI | 原关卡阶段不扩为支线状态容器；UI 展示所属模块的状态 |

允许直接组件引用、Inspector、Prefab、MonoBehaviour、协程和 Unity API。使用现有 `NativeEcaRules` 或小型拆分组件，以最少改动保留清晰的事件→只读条件→动作链。无需独立引擎、通用容器、全玩法 JSON、Schema/能力目录、第二内容包、框架冻结或旧 P1 工具链。

## 4. 输入、显示与资源

- E 只对当前有效互动目标生效；NPC 与记忆、终端、Boss 核心同场时仍遵循现有候选优先级。新选择需要明确的按钮或新按键事件，不能把打开对话的 E 当成自动选项。
- 手机与对话不暂停战斗。选择对话时不得发生重复提交或意外开火切换；关闭/重开清理会话和监听。
- 新玩家可见文案使用简体中文与 FusionPixel；检查场景和预制体引用、缺字及明显溢出。静态角色图或简易标记可用，不因表现占位阻塞功能。
- 保存场景和引用，用户打开 `NativeDemo` 即可试玩；不要求运行场景生成、中文迁移或字体菜单。
