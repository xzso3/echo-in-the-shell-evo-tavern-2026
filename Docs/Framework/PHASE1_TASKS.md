## 2. 通用交接要求

每次任务交接提供：变更文件、实现的能力 ID 与版本、实际执行命令、测试结果、未执行项目及原因、已知限制、对下游的契约变化。校验报告绑定实际版本或摘要；没有运行证据时不得宣称功能通过。

角色名称描述职责。框架开发角色可在所负责代码和契约范围内增加能力；内容角色只写指定内容包、声明式用例和说明，报告由工具生成。验收要求不可自行删除或降低。

现有原型、素材和历史验证文档先作为只读参考。需要复用或修改时说明涉及范围与回归检查；不要批量改动无关场景、资源 GUID 或项目设置。新框架不得反向依赖 PlagueGame 主循环。

## 3. 逐项任务卡

### P1-01 契约冻结与工具链最小验证

- 输入：四份第一阶段文档、现有 Unity/包清单及项目目录。
- 工作：确认纯逻辑程序集和测试宿主目标；最小验证 JSON/Schema 工具在现有 Unity 中兼容；冻结引用、结果、事件、时钟、空间、模块注册及内容清单协议；产出首批 Schema、注册描述约定、合法和非法配置夹具。
- 输出：工程契约版本、依赖版本/许可证记录、可复现的编译验证方法、内容用例 Schema；实际目录生成仍以注册器为准。
- 边界：可调整工程字段和技术默认值并同步文档；不扩展产品范围或把未实现能力标为可用。
- 验收：A01 的工具链和接口部分、A02—A05 的契约夹具；无法验证的环境能力明确标为未执行。

### P1-02 Core 与 ECA 执行

- 输入：01 冻结的契约、能力清单第 1/3/7 节及调度规范。
- 工作：实现注册器、类型化上下文、变量、作用域、事件队列、规则/执行实例、五类组合与等待、四种重入、失败取消、钩子限制及因果追踪。
- 输出：纯 C# Core、用于核心验证的测试模块、注册元数据；测试模块不能作为生产玩法能力导出。
- 边界：不读取 Unity 时间、不访问场景对象、不嵌入样例关卡 ID。
- 验收：A05—A10、A26 的相关核心子例；取消后监听和临时资源有可检查的计数。

### P1-03 内容工具与用例运行器

- 输入：01/02 的契约及注册器，包格式和报告要求。
- 工作：提供可调用的能力导出、内容校验和用例运行入口；检查依赖、导出、类型、作用域、能力与资源引用；输出路径定位；实现可控时间和标准输入驱动；生成绑定摘要的报告。
- 输出：工具入口、实际命令说明、Schema/目录生成物、诊断负例集、通用运行器。初期使用测试模块验证运行器，真实玩法模块在 09 集成。
- 边界：报告不参与源摘要；不能维护一套与 Unity 不同的地图、战斗或目标逻辑。
- 验收：A02—A05、A09、A26 的相关工具子例；期望失败、工具崩溃和未执行有不同结果。

### P1-04 Entity、地图与空间能力

- 输入：Core、地图与实体定义、坐标和端口约定。
- 工作：实现稳定实体身份及生命周期、四层地图加载、边界连接、区域跨越、三类阻挡、动态门、路径与可达性；提供角色体积和弹丸运动所需查询。
- 输出：纯逻辑 Map/Entity 模块、类型与能力注册、空间测试夹具。
- 边界：场景显示交给 Host；重建显示不重置模块状态；旋转/镜像配置在本阶段明确拒绝。
- 验收：A11—A13、A22、A26 的空间和生命周期子例。

### P1-05 Actor、行为与基础战斗

- 输入：04 的空间与实体能力、攻击和表现契约。
- 工作：玩家移动及开火意图；敌人感知和状态决策；ECA 攻击阶段；直线弹丸、冷却、伤害提交钩子、来源快照和死亡清理。
- 输出：Actor/Combat 模块、攻击与行为内容注册、可供 Host 读取的表现状态。
- 边界：不依赖动画回调触发伤害；已发射弹丸按关卡归属清理；不扩展完整装备、Buff 或随机掉落。
- 验收：A10、A13—A17、A26 的战斗子例；同定义多实例和隐藏显示时的逻辑结果可验证。

### P1-06 交互、任务与对话

- 输入：04 的 Entity/Map 接口、交互与任务契约、对话会话协议。
- 工作：候选选择与确认重查；一次性终端；目标跟踪与 all/any/前置依赖；关卡完成校验；JSON 对话会话、选择和取消；注册相应事实与能力。
- 输出：Interaction/Quest/Dialogue/Level 基础模块和测试夹具。01/06 明确任务历史追认使用的本局内事实记录，避免重播副作用。
- 边界：业务状态归属各模块；对话关闭不回滚已提交终端结果；不能开放绕过目标校验的直接完成命令。
- 验收：A18—A22、A26 的流程子例；重复、过时请求和任务历史策略有实际测试。

### P1-07 Unity 宿主与资源接入

- 输入：05/06 的模块输出、资源协议、可复用素材清单。
- 工作：实现显式启动组装、稳定资源 ID 导入映射、Sprite/逐帧动画、地图显示、镜头、输入路由、任务/交互/对话 UI；建立独立测试场景。显示读取逻辑快照，输入进入标准命令入口。
- 输出：Unity Host、必要 Editor 导入/构建适配、资源清单和导入说明、可重复进入的测试入口。
- 边界：不制作内容编辑器；不将关卡摆放、任务或攻击参数写进场景脚本；不把旧 Tab 地图/E 背包/F 对话映射带入新入口。
- 验收：A01、A04、A12—A15、A17—A18、A21—A22、A24—A26 的宿主部分。真实样例全流程与冻结由 09 完成。

### P1-08 样例 A 内容包

- 输入：明确版本的能力目录、Schema、资源清单、四 Chunk 测试任务书和基础验收条件。
- 工作：制作入口、战斗、绕行、终端出口四个区块及连接；一个玩家、一种敌人、一个终端、一扇门、任务与短对话；提供两条路线的声明式用例。
- 输出：A 源内容包、依赖清单、包说明、工具报告。正式运行配置只能引用真实已导出的能力。
- 边界：允许写 A 包及其声明的素材包；缺能力时提交需求，不修改框架代码、不放宽必需目标或验收条件。
- 验收：静态校验及 A20 的 A 包逻辑路线；Unity 表现由 09 集成。

### P1-09 集成验收与框架冻结

- 输入：07 的宿主、08 的 A 包、全部已有测试结果。
- 工作：运行 G1/G2，修复模块之间的接口和实际表现问题，做受影响的原型回归；核查目录与实现一致；记录正式冻结基线。
- 输出：框架版本或不可变源码摘要、能力/Schema/工具摘要、资源依赖版本、实际运行环境、A 的报告及视觉证据。
- 边界：修复必须进入对应模块与通用契约，不能添加 A 包专用分支；尚未跑通时保持未冻结状态。
- 验收：G1/G2 的必需检查全部通过，关键限制有明确记录。

### P1-10 冻结框架上的样例 B

- 输入：09 的只读冻结基线、新内容任务书和相同验收标准。
- 工作：通过配置改变布局、敌人参数和对话；复用已有目标能力，要求两个终端均操作后才能开放出口；制作交战与绕行验证路线。
- 输出：B 源包、声明依赖、变更说明及工具生成报告；记录生产前后冻结摘要对比。
- 边界：只写 B 包和输出报告。发现能力不足则返回能力需求流程；框架有变化必须由 09 重新验证 A 并生成新冻结基线，然后重新开始 B 的冻结验证。
- 验收：A20 的 B 路线、A23，以及 B 相关的其余逻辑和 Unity 检查；所有变化可以归因到配置或资源。

### P1-11 最终验收与交付

- 输入：A/B、冻结基线、全部报告和视觉证据。
- 工作：核对 A01—A26 的相关必需子例、运行说明、包与能力目录版本；检查未执行项目及限制；确认源包能在记录环境中重新导入和运行。
- 输出：最终报告、可复现命令、独立验证场景入口、两份内容包、限制与后续能力缺口清单。
- 边界：不将图形缺陷用静态通过掩盖，不将新框架完成等同于完整首个可玩版本完成。
- 验收：G3，所有必需项通过，第一阶段才标记完成。

## 4. 可复用委派模板

以下模板用于后续明确派发某项开发任务时填写，不会自动创建任务或运行 agent。

```text
任务：<P1-ID 与名称>
目标：<可验证结果>
依据：PHASE1_IMPLEMENTATION_SPEC / CAPABILITIES / ACCEPTANCE 的指定版本
输入：<冻结契约、目录、依赖包与前置交付>
允许修改：<代码模块或内容包的具体路径>
接口约束：<依赖方向、所属状态、可调用能力>
验收：<Axx 子例及实际执行入口>
交付：变更文件、能力与版本、运行命令、结果和未执行项、下游影响
能力缺口：提交场景、所需行为、输入输出、生命周期和验收示例
```
