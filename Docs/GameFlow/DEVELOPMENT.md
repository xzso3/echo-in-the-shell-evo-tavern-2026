## 0. 独立批次边界

批次编号GF01。独立立项、派发、集成、状态跟踪和交付，不作为AI批次增量任务。旧AI／Toolkit成果是输入依赖，不是本批次子任务；不把旧提交或旧通过记录登记为GF01新任务完成。

## 1. 范围与最新决策

交付完整的 **主菜单 → 进入游戏 → 游玩 → 结局 → 结算 → 主菜单／新一局**，以及失败、暂停和局内AI设置分支。

全流程UI/UX由资深游戏UI/UX设计负责人统一处理，采用 **流程／布局草案 → ImageGen草图 → 按草图生成所需美术资产 → 原生Unity UI接入**。风格沿用认可的像素赛博朋克与战术终端，正文、数值、按钮和真实状态由uGUI/TMP实现。

执行优先级：功能快速交付；不写／不跑自动测试，不建探针或回归矩阵，不要求中间人工验收，不设置独立评审轮次。设计草图用于设计决策与制作交接，不构成逐张等待用户审批的开发门槛；若改变已认可方向或产品行为再确认。最终由用户或指定操作者人工校验一次。

不包含演示脚本、评分展示、玩法扩展、新Boss、存档／继续游戏、关卡选择、排行榜、奖励或完整过场重制。角色人设由队友提供；授权后叙事反馈另议，不插入本阶段。

## 3. 场景与界面流程

只需要 **主菜单场景＋一个当前游戏场景**。开局说明、暂停、结局、结算均为游戏场景内的UI／流程状态，不新增结果场景或跨场景结果传输系统。

```text
主菜单 ──AI设置──返回主菜单
  │ 开始游戏
  ▼
加载游戏 → 操作说明 → 开始行动 → 游玩
                              ├─ 平板／合同 → 关闭后续玩
                              ├─ Esc暂停 → 继续／AI设置／确认返回菜单
                              ├─ 死亡 → “意识涣散”失败结算
                              └─ 通关判定
                                  ├─ 归档／逃逸／同化短文本
                                  └─ 新生：第一拳→自主终拳→黑屏→平板接续
                                       ↓ 玩家点击查看本局结果
                                    成功结算
成功／失败结算 → 再来一局／重试 → 重新加载游戏并显示操作说明
成功／失败结算 → 返回主菜单
```

### 3.1 主菜单

三个主要操作：**开始游戏、AI设置、退出游戏**。显示“已配置”或“离线模式”；已配置只说明必要配置存在，不等同于API健康或实际连接成功。测试连接结果独立显示，避免假在线。

未配置或失败仍能开始。复用AI批次离线模式选择，放在设置或开始逻辑中，主菜单不额外扩出存档／继续／选关按钮。退出在玩家构建中退出应用；Editor中不给出假的已退出结果。

### 3.2 开局说明

每一局，包括再来一局和死亡重试，都显示WASD移动、Space开火／停火、E互动、Tab平板说明和“开始行动”按钮。不加剧情过场。

开始行动之前战斗与本局计时均不推进，不允许世界互动提前收记忆或触发Boss；加载阶段可初始化对象，但不要在后台执行遭遇开始／攻击。按钮一次生效，关闭说明后才进入Playing并提交一次Run.Started。若现有初始化依赖先进入Playing，应拆分初始化与开始事件，不能用隐藏的一帧战斗掩盖顺序问题。

### 3.3 正常结束

通关条件与四结局判定仍由现有Quest／Narrative拥有，本阶段只调整呈现与导航。关卡停止接受战斗输入，关闭手机合同、取消未完成AI请求，固定本局结果。

归档／逃逸／同化：显示现有对应短文本，玩家点击“查看本局结果”后进入结算，不自动倒计时切换。

新生：第一拳必须由玩家E触发，自主终拳不由玩家输入触发；黑屏与平板接续保留。接续后的返回键／原“返回游戏”入口替换为“查看本局结果”。关闭请求同样路由到结果，不允许留下无操作入口的黑屏，更不能重新激活战斗。不在拳击、黑屏期间开放Esc暂停菜单。

本阶段可改善既有结局UI和必要美术，不增加整套世界脱落／Glitch关卡动画、角色战斗动画或新剧情。

### 3.4 死亡

死亡标题严格为 **“意识涣散”**。生命归零后本局停止，取消在途AI、关闭平板／合同／暂停菜单，显示失败结算。不新增死亡动画、等待倒计时或四类结局判定。

死亡优先于普通UI打开请求；无论之前处于哪个可操作面板，不能重新回到Playing。保留本局记录直到玩家选择重试／返回菜单；取消合同不能回滚已完成支援，也不新增授权代价。

### 3.5 结算数据

| 数据 | 成功 | 失败 |
| --- | --- | --- |
| 标题 | 四类结局名称之一 | 意识涣散 |
| 一句总结 | 对应真实结局短总结 | 简短失败反馈，不宣称获得某结局 |
| 基础数据 | 本局用时、击败敌人数 | 同左 |
| 人格状态 | 最终同步度、差异度 | 死亡时的同步度、差异度 |
| 关键经历 | 最多三条真实行为 | 同左，无事件则隐藏区域或提示尚无关键记录 |
| 操作 | 再来一局／返回主菜单 | 重试／返回主菜单 |

不加总分、星级、排名或奖励。建议确定性选择三条不同真实事件，优先支援、绕行、记忆选择，缺少则补其他有效记录，不调用LLM生成总结、不臆造“全程无击杀”。此顺序为工程默认，不新增玩法判定。

结果在通关判定／死亡时从现有拥有者抓取只读 `RunResultSnapshot`，至少含本局身份、成功／失败、可空结局、用时、击杀、Sync／Difference、最多三条事件。仅用于稳定展示，不是第二份权威剧情状态，不落盘。终局演出或UI浏览时间不再计入本局用时。

### 3.6 重试、返回与清理

再来一局／重试均重新加载当前指定游戏场景，从头创建新局并显示开局说明；无需再次填写Key。结算返回菜单直接返回；游玩中返回菜单先显示“本局进度不会保存”的确认框。

统一离局顺序：锁定导航防重复 → 使本局请求代次失效并取消HTTP → 取消未确认合同、终结未执行提案 → 清理本局会话与订阅 → 释放本局暂停原因／恢复正常UI时钟 → 载入目标场景。通过现有组件自己的清理入口完成，不能粗暴销毁程序级配置单例。

保留API地址、模型和当前进程Key；清理本局战斗、聊天、提案、合同、计时及结果快照。返回菜单不自动测试连接或发送请求。加载失败显示可操作错误和返回入口，不死锁在被禁用按钮上。

## 4. 暂停、输入优先级与AI设置

### 4.1 暂停原因统一

避免手机和新暂停菜单各自保存／恢复Time.timeScale而相互覆盖。采用一个轻量暂停拥有者管理原因，例如`Intro`、`Phone`、`PauseMenu`、`ReturnConfirm`；设置窗保持父窗口的暂停，不反复恢复再暂停。不扩展为全局服务框架。

业务活跃与战斗推进仍分离：玩家存活且Run有效时可执行暂停中的支援；战斗更新需无暂停原因。不要通过禁用Actor／切换焦点暂停，否则会触发现有清理或Boss重置。

探索、Boss战均能暂停，冻结范围与AI阶段一致：角色／敌人移动、伤害、弹丸、冷却、核心窗口、Buff、本局计时。UI和请求／超时继续运行。终局演出无需战斗推进，但动画时钟必须正常；不要在进入结局时把整个演出冻结。

### 4.2 输入优先级

| 当前界面 | Esc／返回行为 |
| --- | --- |
| 合同覆盖窗 | 取消该合同与提案，返回原聊天位置，不同帧再关手机 |
| 平板普通页 | 关闭平板，释放手机暂停，不同时弹出暂停菜单 |
| AI设置 | 关闭设置，回到打开它的主菜单或暂停菜单；局内继续暂停 |
| 返回菜单确认框 | 取消返回，回到暂停菜单 |
| 暂停菜单 | 等价继续游戏，释放菜单暂停 |
| 普通游玩 | 打开暂停菜单 |
| 开局说明 | 不绕过“开始行动”启动战斗 |
| 新生拳击／黑屏演出 | 不打开暂停菜单，不跳过演出 |
| 结局短文本／成功失败结算 | 使用可见结果／导航按钮，不恢复战斗 |

同一按键每帧只被最上层消费。世界移动、开火、互动、装备输入在菜单打开时屏蔽，关闭后恢复原开火选择；不继承残留移动。文本编辑优先保护输入，按键不透传战斗。

### 4.3 暂停菜单

包含“继续游戏”“AI设置”“返回主菜单”。返回主菜单时确认“本局进度不会保存”，确认退出／取消返回菜单。确认框和设置窗都不使世界恢复；普通结局及死亡不再开放这套菜单。

### 4.4 共享AI设置与提案失效

主菜单与暂停菜单必须复用同一表单与 `CommanderSettings`，不复制API配置或客户端。局内打开设置仍暂停，测试连接可运行且不写本局聊天。

只有实际应用了变化才触发生命周期操作：取消在途游戏AI请求、取消当前待确认合同、将尚未执行AI提案统一标失效，保留聊天和已执行效果。取消表单编辑或无变化保存不应无故清除合同。

建议设置用临时编辑缓冲，点击应用时一次提交；Key留空默认保留已有内存Key，清除Key单独明确操作，避免掩码占位符作为真实Key。沿用已有UI行为时至少保证用户能理解保存／清除语义。

配置提交后新请求使用新设置；旧响应不能在新配置下显示或执行。聊天中旧提案卡保留但标失效。只改配置不清空6轮历史，不重置游戏分数或支援使用次数。首页和局内测试连接互斥占用同一传输，不自动追加模型调用。

## 5. 最小架构与状态衔接

建议新增 `Assets/NativeGame/GameFlow/` 和 `Assets/NativeGame/GameUI/`，不为本阶段新建全局框架或改整个项目程序集。

| 职责 | 建议拥有者 |
| --- | --- |
| 本局阶段、开始、死亡、正常完成 | 现有NativeRunController，最小扩展 |
| 菜单／说明／结局页／结算页显示状态 | 一个FlowPresenter／FlowController，不能自行重复判定胜败 |
| 场景导航与去重 | FlowNavigation；场景引用统一配置 |
| 结算只读数据 | RunResultSnapshot／从现有拥有者读取的构造器 |
| 所有暂停原因 | 现有PhonePause的兼容扩展或唯一替代组件 |
| 设置提交与旧提案失效 | 复用AI会话／支援桥接，补齐单一配置变化入口 |

初始化建议分为`PrepareRun`与`BeginAction`。前者接线、创建共用Combat与会话，后者才进入Playing并发Started；检查NativeCombatIntegration与NativeLevelHost的启动依赖，把启动事件保持一次。工程上也可保留原Run枚举并增加独立UI阶段，避免大范围重命名序列化内容。

UI阶段至少能区分Intro、Playing、EndingPresentation、BirthContinuation、Results、Leaving；暂停是Playing上的覆盖状态，不是新的死亡状态。终局后只接受查看结果和离局，结局状态机仍归Narrative。

## 6. 全流程 UI/UX 与 ImageGen 产线

资深游戏UI/UX任务负责全局视觉一致性，沿用 [认可平板方向](../AICommander/References/tactical-tablet-concept.png) 与已经生成的PhoneUI资产。平板用于通讯，不给所有界面套厚平板外框。

| 界面族 | 布局与核心内容 | 图像资产方向 |
| --- | --- | --- |
| 主菜单／AI设置 | 游戏标题、三个主入口、配置状态；设置表单清晰可读 | 像素数字废弃设施背景、标题装饰／终端边角；文字原生渲染 |
| 开局说明／暂停／退出确认 | 简短操作键位、明确主按钮；暂停后背景变暗 | 共用轻量像素面板、键帽／按钮框，不做额外剧情插画 |
| HUD／世界互动提示 | 生命、开火、目标、现有装备提示；不得遮主要战斗区域 | 小图标、局部边框、状态色；不扩大成复杂仪表盘 |
| 平板／合同 | 延用当前三入口、聊天、提案及合同覆盖 | 复用已认可ImageGen资产，补缺少状态资产，不整套重画 |
| 四结局呈现／新生接续 | 原结局文本、第一拳／终拳／黑屏与结果入口 | 同世界语言的简洁收束；不制作额外角色动画或改结局机制 |
| 成功／失败结算 | 结果标题、少量数据、最多三条行为、两个导航按钮 | 共用结果终端框，成功／失败用有限色彩与标记区分 |

实际流程：

1. 设计者先画覆盖所有界面族的SVG或布局说明，标注数据、按钮、弹窗层级和状态；不只设计一张漂亮主菜单。
2. 用内置ImageGen依据布局与现有参考生成关键界面草图，可一张状态板覆盖相关页面以节省调用；所有UI族都有对应设计说明或既有已认可草图。
3. 设计者按可实现性自查阅读与交互，再按草图拆资源；同风格共用元素只生成一次。用户已经确认风格，不新增逐图审批流程。
4. 用ImageGen生成实际需要的美术资产，保存到项目新资源目录，记录prompt和用途；不要把完整草图裁成一个不可编辑的全屏UI。
5. 原生uGUI/TMP装配真实数据和按钮，复用现有中文字体；最终人工查看游戏内结果。

以16:9现有UI基准和Canvas缩放实现其他窗口尺寸的基本适配，不建立本轮多分辨率测试矩阵。外框用切片或固定角保持像素形状，动态文本必须可换行／滚动。状态由Unity控制，按键图标不替代中文说明。

不显示“战斗已暂停”提示文字。整体深色工业像素材质、绿色通讯、琥珀授权；失败可用克制的失联色，不把失败误画为某个四象限结局。不得将“生命／同步／击杀”等示例数字写进最终贴图。

## 7. 独立批次与输入基线交接约束

AI批次代码已在推进／合入，开始本阶段前确认真实HEAD与任务状态，建立独立批次分支和交付记录，将已有能力作为输入基线复用。首页配置可提取成复用View，平板已有资源直接保留；HTTP、6轮历史、状态白名单、支援执行不重写。

本阶段新增设置变化对提案的失效要求，以及平板终局返回键的新路由，由一个集成写入者统一改动。原AI批次文档仅是基线，其“未完成流程”以本文最新确认补齐，不批量改写旧交付报告或伪造它已验收。

所有功能要求通过程序实现，不依赖制作人员现场手工重置Time.timeScale／场景。产品合法性检查是功能，不因省略开发测试而删除。
