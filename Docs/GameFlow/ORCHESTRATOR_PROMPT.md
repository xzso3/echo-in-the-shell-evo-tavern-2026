必须实现的行为：

- 两个场景层次：现有主菜单场景和当前游戏场景；结局与结算留在游戏场景，不新建结果场景。
- 主菜单三个入口：开始游戏、AI设置、退出；离线可开始，不加存档、继续或选关。
- 每局含重试都显示简短操作说明，点击开始行动才推进战斗／计时，Run.Started只发一次。
- 归档／逃逸／同化显示短文本后由玩家点查看结果；新生保留真实第一拳、自主终拳、黑屏及平板接续，返回入口改为查看本局结果，不能恢复战斗。
- 死亡立即停战斗、取消请求并关闭手机合同，显示“意识涣散”失败结算，不增加动画或倒计时、不判四结局。
- 结果展示真实用时／击杀／同步／差异及最多三条实际行为；无总分、星级、排行榜和奖励。
- 再来一局／重试从头新局；返回菜单清本局战斗、聊天、合同、提案和暂停，保留进程内API配置与Key。
- Esc探索／Boss战可暂停，菜单含继续、AI设置、返回主菜单，离局需确认不保存；手机开时Esc先关合同再关手机，同帧不弹暂停菜单。演出中不开放暂停菜单。
- 共享一个暂停拥有者，设置／确认框不提前恢复世界；暂停不是Run结束，保留暂停中支援。演出和终局手机不能被缩放时钟卡住。
- 首页和暂停菜单复用AI设置；实际配置变化取消请求与待确认合同、使未执行AI提案失效，保留聊天与已执行效果，不重置支援次数。

全流程UI/UX由资深游戏UI/UX设计任务统一：布局草案→实际调用内置ImageGen出关键草图→按草图生成必要最终美术→原生uGUI/TMP接入。覆盖主菜单／设置、开局／暂停／确认、HUD／互动提示、平板／合同、结局／结算。复用已有认可平板外壳和图标，不重画整套；其他界面延续像素赛博朋克，不一律套厚平板。正文、数值和点击区必须动态，不能用整张生成图冒充可操作UI。不添加“战斗已暂停”文字。

NativeRunController／NativeHud／NativePhone最终合并和共享场景保存只由GF01-INT承担，其他任务交新组件或最小补丁；Unity同一时间只有一个任务使用。不重跑NativeDemo旧创建菜单，不覆盖用户未提交Tilemap／字体／资源，不改结局分数规则。保留现有AI通信、工具包焦点实例／多Boss支援适配。
