## 逐项记录与人工复测要求

### GF02-001：CommanderHome 默认 Camera

用户报告场景缺少默认 Camera。后续核实保存场景与创建路径，补齐适合主菜单的相机配置；避免重复创建或重复 AudioListener。复测：直接打开 CommanderHome 可正常呈现主菜单，进入游戏及返回主菜单后仍正常。尚未查看或修改相机配置。

### GF02-002：主菜单美术

删除中文标题，只显示 **ECHO IN THE SHELL**。使用 image-gen 制作具有《攻壳机动队》科技氛围、赛博朋克风格的原创像素 Logo。用户先批准雨夜城市草案，再要求背景帧动画及右下 **CipherWorks** 队伍 Logo，随后表示“上面的制作方向就先这样”。

已生成静态草案、四帧动效草案及可播放预览；这是方向采纳，不是最终动画资源验收。详细资料见 [主菜单设计记录](MAIN_MENU_DESIGN_APPROVED.md)。复测要求：英文标题准确，三个入口完整，主操作醒目，背景循环无明显跳帧或结构漂移，静态文字与两个 Logo 不抖动。

### GF02-003：开始游戏按钮

用户报告文字为黑色且没有高亮。需按已确认美术方向调整文字、底色与焦点反馈，区分正常、悬停、按下、键盘焦点及禁用状态。复测：可用态易读、醒目，不被误认作禁用；与“开始行动”等主操作保持一致。

### GF02-004：AI 设置不可见

用户指出 Viewport 的 Image Color Alpha 为 0 导致内容不可见；截图同时显示 Mask 和 Cull Transparent Mesh。**这是用户提供的原因线索，尚未独立确认根因。** 后续核查透明度、遮罩和裁剪的组合，以及共享预制体 / 创建逻辑，不只修单个实例。

[截图](References/ManualReview/ai-settings-invisible.png)。复测：首页与局内全部设置入口字段可见；滚动、裁剪、输入、测试连接、应用、取消及返回正常。避免改变透明度后留下不需要的大块遮挡底色。

### GF02-005：开始行动按钮

[截图](References/ManualReview/begin-action-low-contrast.png) 显示操作说明弹窗的按钮文字接近黑色，与深底对比不足。后续改为易读亮色文字并统一交互状态。复测：按钮正常可用时不似禁用，点击后流程仍按原规则一次性开始，不因视觉修改改变开局门槛。

### GF02-006：平板对话无回应 / 指定 SDK

用户报告消息发送后没有回应，[截图](References/ManualReview/tablet-no-response.png) 中状态为“已配置”。该状态不等同于 API 可达或请求成功。后续检查发送事件、在途状态、请求、返回解析、聊天绑定与显示全链路。

用户指定使用 [RageAgainstThePixel/com.openai.unity](https://github.com/RageAgainstThePixel/com.openai.unity) 实现对话。**未安装SDK；开发文档阶段已查阅其README，声明支持Unity 2021.3及以上，工程实际兼容性仍未验证。** 实施前需核实 Unity 2021.3.27f1c2 兼容版本、依赖、自定义模型 / Endpoint 支持、现有代理与凭据边界，保留现有配置和必要的服务接口。

复测：真实成功请求能显示用户消息和回复；等待、超时、报错可见且可恢复；“已配置”不冒充“连接成功”。不同供应商兼容性须以实际验证为准。

### GF02-007：恢复 fallback

对照旧手机实现，核实并恢复未配置 LLM、无法连接、超时、接口错误时的本地回应和相关玩法降级；不得只显示错误后让流程停住，也不能将 fallback 文本伪装成真实模型回复。

复测：未接 API 与 API 失败均能获得明确反馈并继续原有允许的玩法；成功与降级路径无重复回复、重复执行或卡死。旧版实际规则尚未审计，具体迁移清单待核对。

### GF02-008：平板功能完整性

“支援”“记录”当前为空白。需逐项比对旧手机全部功能，记录旧入口 / 逻辑、新入口 / 数据绑定、保留情况和缺口；区分未实现、未绑定、渲染不可见及合法空数据。不要将所有空白直接认定为同一原因。

至少覆盖通讯、fallback、支援、记录以及旧手机已有的其他功能。其他功能应以代码和实际流程为准，不预先宣称已迁移。复测：有数据可显示并交互，无数据有明确空状态；效果、状态刷新及跨局清理与既有规则一致。

### GF02-009 / 010：局内 HUD

移除左上旧标题。第一版金属框草图未采纳，第二版轻量像素 HUD 已明确采纳。按 [已确认设计资料](HUD_DESIGN_APPROVED.md) 后续实施；其中包含原截图、批准草图、参考来源、布局和人工复测项。

设计确认不授权修改关卡或删除未知功能。原截图右侧橙条的用途需先核实，若承载玩法状态应保留信息并重新设计。
