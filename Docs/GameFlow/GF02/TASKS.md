## 建议推进方式

先排查004与008，区分显示问题和功能缺失，再设计006/007的兼容接入与降级路径。001和按钮视觉问题可作为独立修复。002与010依据已经批准的方向制作最终资源并接入，最后统一人工复测。

后续执行采用主控＋独立 Sol task thread＋INT 串行集成，禁止 subagent。工作包、文件归属和并发波次见 [并行执行安排](PARALLEL_EXECUTION.md)。本文件准备派发内容，不代表已经创建任务。

## 完成标准

逐项记录改动文件、实现结果、实际验证与未测范围。正常编译不等于真实联网、离线降级、功能迁移、视觉质量或玩家构建验证通过。所有项目当前均未完成开发。

最终人工检查覆盖：菜单 → 设置 → 开局说明 → 局内 HUD → 平板通讯 / 支援 / 记录 → 返回菜单；未配置、真实成功、不可达、超时与 API 报错；常用屏幕比例和分辨率；背景动画循环、按钮状态与文字可读性。具体判据见需求和设计文档。


## 执行工作包说明

以下6个工作包承接上表10项需求；工作包不是重新编号的需求。所有任务都遵守 [开发规范](DEVELOPMENT.md) 与文件唯一所有权。任务自身不得创建thread、subagent或嵌套代理，不写/跑自动测试，不要求中间验收。

### GF02-INT：基线、共享接线与集成

**角色：** Unity集成负责人。首个启动，并持续到交付。覆盖001及所有工作包的最终装配。

**输入：** 最新GF01集成状态、当前主目录差异、GF02全部资料。不得直接采用文档时观察的提交而不核实。

**执行：**
1. 限定范围核实GF01集成头和用户实际测试场景，将必要GF02文档带入可共享基线；登记工作树、分支、场景和未提交输入。不要整理或删除历史工作树。
2. 发布一页BASELINE_HANDOFF.md，写精确基线、文件所有者和保留接口；把声明在现有文件内的接口归属也标明。ART可先开工，其余代码任务在基线明确后开工。
3. 创建/接续唯一codex/gf02-integration。按NET建议处理SDK依赖与程序集；及时合入显示、会话、菜单和HUD的小批提交。
4. 补默认Camera，应用Host、Native和Bootstrap最小接线，绑定Resources、资产和场景；必要时在唯一Editor中保存.meta。
5. 集中正常导入编译，直接修复装配导致的阻断；不跑测试与自动巡检。产出FINAL_HANDOFF.md，维护集成映射。

**可写/禁止：** 见并行文件所有权表。用户未提交字体、Tilemap和设置不得覆盖；不重跑一次性创建菜单。

**交付：** BASELINE_HANDOFF.md、集成提交、实际启动路径、依赖版本、装配结果、编译结果或具体阻断、最终人工清单。代码交付与人工通过分开。

### GF02-NET：SDK传输

**角色：** Unity网络接入开发。覆盖006的传输部分。

**输入：** 冻结基线、ICommanderTransport/结果类型、CommanderSettings字段、指定SDK仓库。

**执行：** 选定具体SDK与依赖版本；实现兼容现有接口的适配；映射Endpoint和模型；完成非流式请求、取消、非缩放时钟超时、主线程回调、异常归一和一次性终态；测试连接保留独立语义。先告诉CHAT实际结果语义和保留签名，不等待全量SDK接入才沟通。

**可写：** Commander/Transport及新增局部适配。**禁止：** 会话fallback、平板、场景、配置持久化、Packages直接修改。依赖和asmdef需求交INT；不得新造第二套全局配置。

**交付：** 适配代码提交、SDK_DEPENDENCIES.md（版本、依赖、来源、包变更建议、Endpoint映射和限制）、现有初始化兼容方式。文档查阅不算兼容性已验证，编译由INT完成。

### GF02-CHAT：会话、降级与平板完整功能

**角色：** 玩法/对话整合开发。覆盖006会话、007、008。

**输入：** ICommanderSession、传输语义、旧NativePhone/Proxy、Support/Narrative服务及平板绑定。

**执行：**
1. 边阅读边填TABLET_MIGRATION.md，覆盖开发规范中的旧功能，不把审计另立大阶段。
2. 先恢复本地主题、支援/记录实际数据与动作及空状态；检查平板Viewport/Mask，同菜单UI线共享原因结论而不抢工厂文件。
3. 打通Send→玩家消息→等待→结果；唯一会话层负责失败fallback；无配置不禁掉本地通讯。SDK未就绪时基于现有接口完成，不写mock。
4. 保留合同、授权、前置条件、一次性次数、计分归属、最终节点/新生接续及Toolkit适配；不从UI直接改玩法分数。
5. 处理事件订阅/释放、取消/换局/配置变化迟到回调；保留Draft恢复和手动重试，不自动无限重试。

**可写：** Commander/Conversation、CommanderTabletView、CommanderUiFactory、CommanderTabletRunAdapter、自身局部适配。**禁止：** NET传输、Menu UI、Native/Host共享最终接线、Support/Narrative规则改写。

**交付：** 代码、逐项迁移对照（旧入口/新入口/真实调用/是否缺口）、共享接线说明和未测范围。不得用“页面已有空状态”标记支援迁移完成。

### GF02-UI：设置、按钮和菜单接入

**角色：** Unity uGUI界面开发。覆盖003、004、005与002的接入。

**输入：** GF01菜单/设置/开局实现、批准主菜单草图、ART资源约定。

**执行：** 修所有入口共用设置Viewport，核实而非假定Alpha单因；修开始游戏和开始行动文字/背景的全部状态；定义最小共用颜色与图像槽位；移除中文游戏标题，接入英文Logo、CipherWorks与三菜单；实现轻量循环帧播放器及启停；运行状态文字仍绑定真实数据。前期可用现有占位布局，不为等待图像停工。

**可写：** GameUI/Menu、GameUI/Intro、独立动画组件。**禁止：** 场景、CommanderTabletView/Factory、Native共享接线、HUD、依赖。新资源目录资产由INT绑定。

**交付：** 菜单/设置/按钮/动画代码、资源槽位和装配说明、各状态颜色。最终资源缺失应报告，不能把整张带字草图当已实现菜单。

### GF02-ART：最终图像和循环帧

**角色：** 像素游戏美术。覆盖002和010必要图像。

**输入：** 两份已批准设计、归档图片、实际项目像素风资源。不得重新要求用户批准已确认方向。

**执行：** 实际使用image-gen产出纯背景、局部雨/水/灯光帧、精确英文标题、CipherWorks及必要HUD图标；与UI/HUD提前约定尺寸/槽位；先交可用静态层与Logo，再交稳定循环帧；保留清晰像素边缘和正确透明度。不要重画平板，不给文字正文出整图，不生成无需求的额外界面。

**可写：** GameUI/Art/GF02以及ASSET_MANIFEST.md、prompt。**禁止：** 场景、UI代码、全局导入配置。需Editor的导入交INT。

**交付：** 独立资源文件、帧序列或图集布局、建议时长和循环顺序、尺寸/透明度/导入建议、prompt及源/最终用途。不仅交四格草图；生成失败不能静默改成程序噪声冒充image-gen帧。

### GF02-HUD：第二版局内HUD

**角色：** 像素游戏HUD开发。覆盖009、010。

**输入：** 已批准第二版、GF01 NativeHudView与真实数据来源、ART图标约定。

**执行：** 左上紧凑生命、右上任务线索、左下开火/统计/装备、右下平板提示；去旧标题、厚框与重复大标签。绑定真实数值和可用性，像素图标统一；状态改变才刷新必要内容。定位未知橙条的信息归属，保留应有玩法信息。考虑16:9/16:10/较低分辨率锚点、文字换行、边距和裁剪。

**可写：** GameUI/Hud及自身局部显示组件。**禁止：** NativeHud/Run最终接线、菜单工厂、场景、角色/地图和计分规则。

**交付：** HUD代码、字段/数据源映射、NativeHud最小装配需求、用到的图像引用说明。资料中的示例数值不能硬编码为真实UI。
