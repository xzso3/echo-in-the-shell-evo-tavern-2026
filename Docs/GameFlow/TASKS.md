## 1. 执行规则

采用用户指定的 [主控模式](codex://threads/01a0ca99-e997-7733-9a45-d4ee7b146ff8)：主控只管文档、派发、协调、交付核对；独立task thread执行代码、美术和Unity；GF01-INT串行集成。禁止subagent／spawn_agent及执行任务嵌套代理。

执行任务指定 `gpt-6-sol`、`thinking:xhigh`，要求实际请求 `service_tier:priority`；按主控当前可用配置核验，不虚构工具参数，不把prompt当设置证据。使用最新用户授权并发上限，不硬编码旧5线程或本会话subagent槽位。沿用主控已确定的priority缺口处理规则，不为它新建工程。

时间优先，不写／不跑自动测试，不做中间验收／独立审查线程／探针／夹具／截图矩阵。正常导入和编译出错直接修；其余问题在最终人工检查后定点修复。设计产物仍须实际生成并落地，不用“省测试”代替交付。

## 2. 任务卡

### GF01-00：最小接口与基线交接

- 负责人：独立执行任务；主控记录结果。
- 内容：只核对最新Run、Home、Phone、Pause、Session／Support接口和实际目标游戏场景；冻结开始行动、暂停原因、结果快照、场景导航及设置应用入口。
- 交付：一页接口约定或最小公共C#定义、当前可集成基线、共享文件归属。不做全仓审计和历史SHA追溯工程。
- 前置：阶段正式启动。解锁其他任务。

### GF01-01：主菜单、开局与离局生命周期

- 新代码范围：GameFlow/Navigation、GameFlow/RunLifecycle；共享RunController改动由本任务提出、INT合入。
- 内容：主菜单三个入口；启动游戏后说明门槛；开始行动一次生效；再来一局／重试／返回菜单／退出；统一场景选择、防重复导航、离局清理。
- 交付：可绑定接口及现有HomeBootstrap适配，不设计第二套API设置客户端，不修改地图。
- 依赖：GF01-00。UI暂用已有组件和占位结构，等待UX资产即可替换。

### GF01-02：暂停菜单、设置复用与输入路由

- 新代码范围：GameFlow/Pause、GameFlow/Settings；独占Pause／设置桥接改动建议。
- 内容：统一暂停原因；Esc优先级；继续／AI设置／返回确认；局内设置保持暂停；实际配置变化取消请求／合同、失效未执行提案且保留聊天与已执行效果。
- 交付：可复用设置View绑定、菜单状态与暂停API、本批次所需Commander兼容修改；不重写HTTP和支援业务。
- 依赖：GF01-00，可与GF01-01／GF01-03及UX并行。

### GF01-03：结局衔接、死亡与结果数据

- 新代码范围：GameFlow/Results、GameFlow/Ending；NativeEndingSequence／Narrative只读数据入口的必要补丁由本任务提出。
- 内容：只读RunResultSnapshot、三条真实事件选择、成功结局呈现→主动查看结果；新生接续返回键路由；死亡“意识涣散”立即失败结算；终局不可恢复战斗。
- 交付：结果Presenter接口、结局UI阶段与原机制兼容接线说明。不得修改结局阈值或新增死亡动画。
- 依赖：GF01-00；使用GF01-01导航、GF01-02暂停接口，不重复实现。

### GF01-04：资深游戏UI/UX设计与ImageGen美术

- 范围：GameUI/Art、GameUI/Design及相关新资源，不改共享Native场景。
- 内容：主菜单／设置、开局／暂停／确认、HUD／互动提示、平板／合同、结局／结算全界面族设计；复用已认可平板，逐族以布局草案→ImageGen草图→ImageGen资产流程完成。
- 交付：布局和层级规范、真实草图、最终可用Sprite、简短资源用途与prompt记录。优先共享面板、按钮和图标，不一页一整张背景。
- 可在GF01-00同时开始阅读现有资产；不恢复旧UI-01，不把“资深设计师”仅当文字角色而不交付图像。

### GF01-05：主菜单／开局／暂停界面装配

- 范围：GameUI/Menu、GameUI/Intro、GameUI/Pause及独立Prefab／装配代码。
- 内容：真实按钮和表单、加载／错误反馈、开局说明、局内返回确认；主菜单和暂停菜单复用同一AI设置View。
- 前置：GF01-00接口即可开始原生布局；最终消费GF01-01／GF01-02与GF01-04资源。不等图片生成结束才动工。
- NativeHud输入与共享场景交GF01-INT接入，不与另一个UI任务争写。

### GF01-06：HUD／结局／结算与平板末端接入

- 范围：GameUI/Hud、GameUI/Results、GameUI/Ending及独立Prefab／装配代码。
- 内容：统一HUD与互动提示，成功／失败结果布局、最多三条行为、新生结果按钮；复用平板美术，补齐末端路由和同风格表现。
- 前置：GF01-00；最终消费GF01-03、GF01-04。不重做聊天系统，不把运行时快照写成资产固定文本。

### GF01-INT：串行集成与交付

- 独占：NativeRunController／NativeHud／NativePhone最终合并、HomeBootstrap、共享场景、Build Settings、公共字体引用以及跨任务冲突解决。
- 内容：只合本批次任务交付的新提交；使用现有CommanderHome和当前游戏场景，不重复导入旧祖先链；单一Unity时段保存与正常编译；移除被新流程替代的旧UI入口，避免两套结果面板叠加。
- 交付：统一可玩版本、入口与操作说明、最终人工检查单。保留已知未测状态，不因没有自动测试编造通过记录。

## 3. 并行安排

| 批次 | 可以同时推进 | 必须串行的工作 |
| --- | --- | --- |
| A | GF01-00；GF01-04阅读既有参考、做布局草案 | 冻结少量接口与文件所有者 |
| B | GF01-01、GF01-02、GF01-03；GF01-04生成草图／资产；GF01-05/B按固定接口搭原生布局 | GF01-INT滚动合入公共接口和已完成片段 |
| C | GF01-05／GF01-06绑定真实数据并替换资源；原功能任务处理实际接线冲突 | GF01-INT完成共享Native入口与场景保存 |
| D | 仅修最后人工发现的阻断 | 人工核对一次，记录交付 |

按可用执行名额开展，不为八个工作包各开空等任务。可把GF01-00与GF01-01顺序交同一独立thread；GF01-05／GF01-06内容较小时可合并为一个线程，但UI设计与程序尽量并行。GF01-INT占执行名额，Unity始终只归一项。

关键路径：`GF01-00 → GF01-01／GF01-02／GF01-03会合 → GF01-05／GF01-06与最终资产会合 → GF01-INT → 人工校验`。没有用户要求，不添加中间测试门槛、逐图确认轮次或额外发布平台。

## 4. 修改归属与交接

业务任务优先在新目录提供组件，修改共享Native代码时交明确补丁给INT。多个任务不得各自重写NativeRunController或维护独立Time.timeScale恢复逻辑。

主控台账只记录任务ID、threadId、hostId、工作树、基线／交付提交、允许路径、依赖、模型／tier状态和Unity使用者。执行任务回报功能、入口、提交及阻断即可，不要求测试报告或哈希审计。

首批任务从同一最新集成基线创建独立工作树，变更接口后同步消费者；集成期间用户的Tilemap场景、字体和未提交资源不得覆盖。主控不自己结束用户Editor，出现共享场景写入冲突就串行处理。

## 5. 最后一次人工校验

这是最终产品操作核对，不是路演流程，也不需要穷举四结局、全部网络错误和所有窗口尺寸。

1. 主菜单能开始、进入AI设置和退出；未配置AI仍可进入。开局说明出现，点击开始前战斗与计时不推进。
2. 游玩中Esc暂停，继续可恢复；返回主菜单先确认，取消仍留暂停；AI设置关闭回暂停，世界不提前恢复。手机合同／手机本体Esc逐层消费。
3. 实际应用一项配置变化后聊天保留、待确认合同取消、旧AI提案不能执行，已完成效果保留。新请求使用新配置；Key无需在重试／返回菜单后重填。
4. 正常结束的结局页需主动查看结果；新生接续入口能进入结果、不回战斗、不停在无入口黑屏。死亡显示“意识涣散”且无新增等待动画。
5. 结算展示真实数据／最多三条行为，无星级总分；再来一局／重试重新显示说明，返回菜单无旧本局残留。
6. 人工看当前游戏界面：主菜单、HUD、暂停、平板和结果风格一致，中文可读、按钮能点；ImageGen资产确实使用，无“战斗已暂停”提示和动态文字贴图化。

未走到的分支如实标未测，不用自动探针补齐。本轮没有人工操作者时先交“开发完成、待人工校验”的版本，不扣留代码等反馈；后续只修复人工报告的实际阻断。保留未改功能既有实现，不把未检验的正确性写成保证。
