# 实施任务、并行安排与最终人工校验

状态：本阶段已启动；任务与提交的实时状态见[状态台账](STATUS.md)。不恢复已取消 UI-01。架构与具体协议见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 1. 主控模式

采用 [接续会话并主控推进](codex://threads/01a0ca99-e997-7733-9a45-d4ee7b146ff8) 的模式：主控只做文档、调度、依赖协调与交付核对，代码／Unity／Git集成由独立执行task thread承担。禁止subagent、spawn_agent和执行任务嵌套代理。

执行任务明确指定 `gpt-6-sol`、`thinking: xhigh`、请求级 `service_tier: priority`。主控记录实际配置；当前创建／续派工具若无service_tier字段，不伪造参数。按实际支持的设置配置并如实记录缺口，不为核验tier建立额外测试工程。

并发上限采用主控当时最新用户授权，不将旧文档的5线程上限当常量。此阶段最多需要六个相互独立的实现工作流加一个集成任务，依赖未就绪不填满名额。各任务可安全复用已有独立thread，但不得自动恢复已撤销任务。

启动时记录当前集成SHA、工作树及用户改动；依赖此基线创建独立工作树。主控用create_thread／send_message_to_thread／wait_threads／read_thread管理，保持threadId、hostId和提交对应表，优先有界等待和已有结果。代码有可合入增量就交INT-AI，不等整波全部完成。

## 2. 最小公共边界

AI-00只冻结以下签名和数据含义，建议一页说明加必要C#定义，不做多天设计审查：

- 设置读取／更新、最终请求URL、连接检查与取消。
- `SendAsync`的消息请求、成功／失败／取消结果；不带游戏写操作。
- Snapshot内可公开字段、支援option_id到游戏选项映射。
- Session的Send、Cancel、Reset、消息更新事件及Busy状态。
- Proposal的ID／状态、OpenContract、Accept、Reject／Cancel、实际结果回调。
- Phone Open/Close及暂停获取／释放；Active与Advancing的区分。

接口默认由AI-00负责，后续消费者提出最小调整给INT-AI统一更新，不各写一套类型。轻量数据对象放Native程序集，不让工具包Runtime反向依赖本阶段UI。

## 3. 可直接派发的任务卡

### AI-00：接口与现场基线（短串行）

交付：实际最新集成基线、共用数据与接口、目标场景／首页接入方式、共享文件所有者。只读重点为Phone/Hud、Support、Run、SafeNode和Toolkit焦点适配，不重新调研整个工程。决定使用UnityWebRequest最短直连路径；若依赖已有JSON库直接使用。完成即可解锁后续任务，无探针、无测试门槛。

### AI-01：配置与HTTP

允许路径：Commander/Transport、Commander/Configuration。交付C#配置生命周期、地址规范化、一次非流式请求、Bearer认证、真实时间超时、取消、连接检查和错误分类。首页UI由UI-03绑定，不自建第二套界面。不读取旧代理文件覆盖新设置，不写入Key。依赖AI-00，独立于地图与美术。

### AI-02：快照、会话与模型输出

允许路径：Commander/Context、Commander/Conversation及公共协议消费者。交付仅已知信息的快照、6轮请求历史、单请求状态、有限JSON解析、run／request代次隔离、草稿／错误表现数据。定义prompt不泄露隐藏故事，不新增工具调用。依赖AI-00；可先写业务实现，实际HTTP接入等待AI-01，不为等待创建假模型系统。

### AI-03：现有支援桥接

允许路径：Commander/Support；必要的NativeSupportController／INativeSupport变更由此任务独占并交INT合入。交付合法选项读取、提案ID及终态、双重校验、合同UI所需真实数据、现有Support调用、实际结果消息。保留已集成多Boss／焦点玩家和每局使用限制。不得在快照查询中调用有副作用的Request来探测可用性，应提供窄的只读查询。依赖AI-00；和AI-02通过固定数据类型并行。

### AI-04：暂停与生命周期

允许路径：独立Pause组件、NativeRunController／SafeNode及必要战斗推进守卫；NativeHud最终接线交INT。交付统一暂停入口、时钟保存／恢复、Update与输入守卫、暂停可支援、最终选择转演出／终局手机保护、安全节点无敌近限制和重开清理。改动共享Combat时先与INT确定本轮文件所有者，不禁用Actor来暂停。依赖AI-00，可与网络／设计并行。

### UI-02：资深游戏UI/UX与最终美术

允许路径：PhoneUI/Art及设计说明。继承认可SVG／ImageGen方向，补足合同、错误、等待和禁用状态；调用内置ImageGen生成最少必要资产，交付素材、布局尺寸／切片建议及prompt记录。中文和动态数值不烘焙。不得重新创建多套风格候选，不直接覆盖NativeDemo。与AI-01～04并行，不依赖真实API。

### UI-03：首页与平板实现

允许路径：PhoneUI控制器、Prefabs及可显式调用的装配代码。按冻结接口先搭原生uGUI/TMP：首页配置、聊天与输入、提案卡、合同覆盖、支援与记录页、取消／关闭／重开入口；最终接UI-02素材。保留原剧情合法操作和手机结束接续。不在UI里重复实现HTTP或计算代价。依赖AI-00即可搭结构，最终依赖AI-01～04与UI-02交付，不因美术未到而停工。

### INT-AI：持续集成与最后交付

独占NativePhone/Hud最终版本、共享场景保存、公共字体引用、首页启动接线及必要Build Settings变更。集成实际新提交，不引入旧分支祖先，不捆绑用户修改。协调暂停、原最终选择与新合同输入优先级；清除本轮触及位置中与新规则矛盾的旧提示（例如“手机不暂停”）。只处理实际编译／接线阻断，不建立中间测试关口。

最后形成可运行入口、资源列表、配置说明和人工检查单。代码和资源先落到统一版本，再由人工一次校验。需要Windows可执行文件时沿用用户手工构建流程或后续明确安排，不擅自新建发布服务。

## 4. 并行批次与关键路径

| 批次 | 并行工作 | 集成工作 |
| --- | --- | --- |
| P0 | AI-00核对少量代码并冻结共用边界 | INT-AI确定工作树、共享文件及Unity占用 |
| P1 | AI-01网络；AI-02会话；AI-03支援；AI-04暂停；UI-02设计；UI-03原生布局，可按可用名额分批 | 按就绪增量合入，不等待完整批次，不安排测试 |
| P2 | 原任务修实际接线冲突；UI-03替换最终资产并绑定真实状态 | INT-AI统一首页、手机、合同、暂停与重开 |
| P3 | 仅处理人工发现的阻断 | 人工最后校验一次，交付结果与未测范围 |

关键路径：`AI-00 → AI-01/02/03功能会合＋AI-04暂停＋UI-03 → INT-AI → 最后人工校验`。UI-02与程序并行，现成草图只作为已定方向，最终仍需将生成资源实际用于UI。

不要按8项任务创建8个长期空等线程。可让同一独立task thread在明确交接后顺序承担兼容任务；有不同文件的独立工作才并行。Unity只由一个任务使用，设计生成图片和纯C#可继续进行。

## 5. 文件冲突和交接

NativePhone/Hud只由INT-AI写最终版本；UI任务以新增Presenter／Prefab接入说明交付，暂停任务以API与最小调用点补丁交付。Support由AI-03独占，Run/SafeNode由AI-04独占；公共DTO由AI-00／INT维护。设计者只写新资产，不动字体源、Packages或ProjectSettings。

回报只需：任务ID／threadId、基线与交付提交、变更目录、可调用入口、实际阻断、待集成事项。没有测试报告要求，不编造通过记录。不花时间建复杂审计、哈希清单或每轮截图归档。

## 6. 唯一人工校验清单

本清单是开发完成后的功能核对，不是演示流程；由用户或指定人工操作者执行，不由脚本冒充。

1. 首页填写地址／Key／模型并测试连接，进入游戏；失败提示可理解，也能离线进入。重开本局仍有Key，退出重启不自动保留Key。
2. 安全节点打开平板，游戏停住；可阅读和发送真实消息，获得对白及合法提案。非安全节点不能输入，附近敌人不再影响节点内输入。
3. 查看一张合同，核对真实效果／记忆／授权／代价；接受支援即时生效，关闭后战斗从暂停点继续。拒绝或关闭的合同不能再执行。
4. 等待时取消／关闭手机后不再出现迟到回复；重开没有旧消息或合同。手机内切页仍可阅读，不因等待卡住。
5. 界面文字、滚动、返回键可用，外壳与聊天区域符合认可草图；未出现“战斗已暂停”文字，原记录／支援／剧情必要入口仍在。

不要求穷举每个错误、每个结局、不同平台或多分辨率，不开发自动化检查。人工未执行时可交付“开发完成、待人工校验”的版本并继续交接，不能声称人工已通过。若没有真实API凭据，只注明联网待人工填写Key后确认，不要求用户在聊天中公开凭据。
