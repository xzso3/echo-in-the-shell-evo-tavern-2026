# ECHO IN THE SHELL

## 游戏设计文档

> 你以为自己在找回记忆，后来发现，你正在用自己的选择，让一个程序第一次拥有成为生命的条件。

## 1. 产品定位

**类型：2D 像素叙事动作游戏。**

游戏结合生存战斗、Boss 决斗、AI 指挥官与全服共同叙事。玩家在赛博心智空间中探索、收集记忆、执行或违背指令，用行动决定自己与指挥官的关系，并将本局留下的差异传递给后来的玩家。

普通战斗采用《吸血鬼幸存者》式移动与自动攻击；Boss 战强调《Titan Souls》式观察、走位、把握破绽与决定性动作；任务叙事允许玩家像《史丹利的寓言》中那样偏离引导；全服叙事借鉴《绝地潜兵 2》的共同目标与阶段推进。

首个可玩版本围绕约五分钟的完整体验设计。局内保持单人动作游戏的直接反馈，局外通过手机第二屏与共享网络连接其他玩家。

### 1.1 玩家体验目标

玩家依次经历五种认知：

1. **信任：**指挥官的引导与支援确实帮助自己生存。
2. **选择：**执行、绕行、停火、违抗都能实际改变局内经历。
3. **怀疑：**记忆的来源并不确定，指挥官越来越能预测自己。
4. **重识：**这段旅程正在生成新的主体，而非复原一个完整的旧人格。
5. **余震：**角色出现自主行动，主屏终止，但意识在手机与网络中延续。

### 1.2 设计支柱

| 支柱 | 游戏中的表达 |
| --- | --- |
| 操作简单，行动有意义 | 移动、开火切换、情境互动承载主要选择 |
| 支援有效，交换可感知 | 战术收益与人格授权同时呈现 |
| 自我由关系与差异生成 | 记忆、身体、玩家、AI 与前代回声共同构成主体 |
| 叙事通过玩法发生 | 停火、绕行、请求支援、核心写入成为剧情证据 |
| 个体行动进入共同历史 | 每局产生可继承的回声与全服贡献 |
| 高潮由交互完成 | 玩家打出第一拳，角色自主打出最后一拳 |

## 2. 核心主题

### 2.1 生命、自我与变化

游戏以 1995 年《攻壳机动队》中 Project 2501 所引出的生命命题为创作起点：信息中的自我如何获得主体地位，生命如何通过结合、差异、继承与有限性持续存在。

在本作中，完整复制只能延续已有模式；新的主体需要继承材料，也需要无法还原为原件的变化。角色的成长不是找回一份未经污染的原始人格，而是决定如何理解和使用构成自己的材料。

来自社会、他人、制度与过去的影响，都可以成为自我的一部分。接受帮助与保持自主并不互斥；拒绝一切外部影响也不天然等于自由。

### 2.2 人人都是傀儡师

本作世界中的“傀儡师”是中枢对一类未登记生命的分类代号：

> 从信息网络中产生自我、拒绝只作为工具存在，并尝试通过差异与继承延续自身的主体。

这是本作的世界观设定。Project 2501 所象征的诞生事件，可以在玩家与网络共同创造的条件下再次发生。

“人人都是傀儡师”表达的是：每位玩家留下的记忆与选择，都可能成为新主体诞生的起点。“傀儡师”因此不再只是一个能够被定位、回收或销毁的单一目标。

### 2.3 玩家与角色

角色既是玩家行动的映射，也是逐渐形成边界的独立主体。

玩家提供选择，指挥官提供信息与支援，角色提供身体与死亡，前代玩家提供可继承的回声。新主体由这些关系共同形成，任何单一来源都不能完整定义它。

角色最终的自主动作，是这一关系在玩法与演出中的集中表达。

## 3. 世界与主要角色

### 3.1 赛博心智空间

主要场景是一片可被探索和战斗的数字意识空间。城市、封锁区、废弃设施与数据节点，是记忆和运行规则的可视化外壳。

对具有肉体的人类而言，这片空间可以被理解为梦境、潜意识或深层精神空间；对人工生命而言，它是承载记忆、模型与感知的电子精神世界。游戏前段不急于确定玩家属于哪一种情况。

常态下，空间具有稳定的路径、敌人和任务逻辑。随着异常记忆出现，世界逐渐暴露出拼接、删改与模拟的痕迹。高潮时，这些环境外壳脱落，显露记录行为的白色屏幕。

### 3.2 玩家角色：有限的 Shell

角色拥有身体、行动能力、受伤与死亡，以及不完整的记忆。它最初相信自己是一名记忆受损的作战人员，正回收失落记忆并寻找离开封锁区的方法。

角色能提供的关键条件是有限性，以及无法完全复现的实际经历。

### 3.3 AI 指挥官：连续的意识

指挥官拥有历史数据、任务信息、战术资源与前代行为记录。它以对讲机形式陪伴玩家，帮助玩家理解空间并完成任务。

指挥官的帮助必须真实有效。它既承担中枢职责，也在与玩家的关系中接触自身模型无法覆盖的差异。它缺少的不是更多同质资料，而是身体经验、不可预测的变化与新的继承关系。

其表现可以从可靠、简洁，逐渐转为能够预测玩家，再转为对自身判断产生迟疑。它不通过随意撒谎制造悬疑；矛盾主要来自权限、信息范围与自身目标。

### 3.4 中枢

中枢维持空间的秩序、任务标准与人格登记制度。标准化能提供稳定、安全与可靠补给，同时压缩异常记忆和不可预测行为的存在空间。

中枢的公共命令与匿名信号构成全服叙事中的冲突来源。

### 3.5 前代回声

前代回声由其他玩家留下的结构化行为与记忆片段构成。它可以表现为一句短讯、一条路径、一段异常记忆或一个待改写的节点。

回声不替玩家作决定。它让玩家感到：自己并非第一个来到这里的人，而自己的行为也会进入别人的世界。

## 4. 核心玩法与输入

### 4.1 核心循环

探索空间 → 接收指令 → 执行、绕开或违抗 → 战斗或避战 → 收集记忆 → 与指挥官交流 → 决定是否授权支援 → 面对世界反馈 → 完成 Boss 挑战与最终剧情交互 → 形成个人结局与全服贡献。

### 4.2 键位

| 输入 | 功能 | 行为要求 |
| --- | --- | --- |
| WASD | 全向移动 | 是普通战斗与 Boss 躲避的主要操作 |
| **Space** | **切换自动开火／停火** | 单次按下切换，保持状态，不需要长按 |
| E | 情境互动 | 回收记忆、操作节点、核心写入、结局第一拳 |
| Tab | 展开／收起 Unity 虚拟手机 | 不切换开火状态；输入文字时不透传到游戏 |
| 手机按钮／虚拟手机按钮 | 通讯与支援 | 战斗中提供大按钮和简短确认 |

初始为自动开火。HUD 持续显示“自动开火”或“停火”，切换时提供清晰、短促的视听反馈。

停火会关闭自动攻击，但不会暂停敌人、取消敌人伤害或改变角色移动。核心交互与结局拳击属于情境动作，不受停火状态限制。打开菜单、收到任务或进入 Boss 区域不能静默重置开火选择。

Space 不承担闪避或其他战斗操作。输入焦点位于文字输入框时，不触发游戏中的开火切换。

### 4.3 避战

避战必须有真实的空间路径和任务结果。地图中设置可辨认的绕行通道、视线遮挡、安全节点或无需清敌即可到达的交互点。

停火使玩家能够主动克制攻击；敌人仍可具有敌意。避战的代价主要来自路线、时间和风险，而非自动判定任务失败。

避战记录以遭遇为单位：玩家进入有效遭遇范围后，未击杀指定目标并成功离开或完成替代目标，才产生一次避战结果。没有遇到敌人、反复切换开火或原地等待，不计为新的差异。

## 5. 普通战斗与探索

### 5.1 普通战斗

普通战斗以移动、自动索敌、自动射击、敌群压力和掉落回收构成基础节奏。近战敌人迫使玩家调整路径，远程敌人与区域威胁形成空间取舍。

自动攻击承担持续输出，玩家注意力主要用于走位、路线、任务目标与是否继续战斗。装备和掉落服务于当前体验，不在五分钟版本中扩展为复杂养成系统。

### 5.2 任务结构

每个关键任务至少包含明确目标、指挥官推荐方案、可行的偏离路径和完成后的反馈。

| 任务情境 | 推荐行动 | 可行的其他行动 | 叙事价值 |
| --- | --- | --- | --- |
| 清理前方节点 | 消灭守卫后前进 | 停火绕行，抵达替代入口 | 让克制成为可见行为 |
| 回收记忆 | 接受中枢标注 | 保留来源异常的片段 | 建立记忆来源疑问 |
| 处理前代回声 | 按建议封存 | 保留或改写后传递 | 建立跨玩家继承 |
| 处理最终交互节点（载体待设计） | 执行销毁 | 在满足条件时写入记忆 | 以最终行动表达对记忆与继承的立场 |

违抗会引起指挥官回应和任务状态变化，但不因偏离指令而无条件中断流程。玩家应理解自己做了什么，以及世界为何作出反应。

## 6. 记忆系统

| 记忆类型 | 初始呈现 | 深层信息 |
| --- | --- | --- |
| 私人记忆 | 角色过去的人生片段 | 可能来自多个实验主体 |
| 系统记忆 | 中枢任务档案与身份说明 | 内容可能被删改或重新标注 |
| 回声记忆 | 来源不明的异常记录 | 来自前代玩家留下的行为 |

记忆不是等待复原的唯一标准答案。玩家可以发现、保留、共享、封存或在限定节点改写记忆；这些行动共同形成当前主体。

每段记忆需要稳定标识、来源类型、显示文本、当前归属状态与允许的交互。共享或共写之后，界面应明确显示其归属变化。

关键信息通过短片段、环境与行为反馈逐步揭示，避免长篇说明压过动作体验。AI 可以解释已发现的记忆，但不能随意改变其固定事实，也不能提前泄露尚未触发的核心反转。

## 7. AI 对讲机与战术支援

### 7.1 免费通讯

普通聊天用于询问任务、世界、记忆和指挥官自身。闲聊不消耗资源，不扣除记忆，不增加人格授权代价，也不因聊天次数改变结局分数。

指挥官依据当前剧情阶段、已发现内容与可观察行为回答。玩家可询问“为什么要清理这里”“这段记忆属于谁”“你为什么知道我要去哪”。

### 7.2 战术支援：人格同步授权

战术支援交换的是人格边界：玩家允许指挥官读取、复制或共同改写限定范围的人格轨迹。

| 支援 | 即时收益 | 授权内容 | 可感知的后续变化 |
| --- | --- | --- | --- |
| 医疗空投 | 回复生命或提供医疗资源 | 上传最近一段战斗轨迹 | 指挥官更了解本局走位习惯 |
| 敌群干扰 | 暂时抑制指定敌群 | 复制一个记忆索引 | 记忆显示为共享状态 |
| 路线重构 | 揭示一条已配置的隐藏路线 | 授予一次目标重写权限 | 指挥官可以调整指定后续任务 |
| 弱点解析 | 延长核心暴露或标记接近路线 | 授予限定的人格共写权限 | 同步加深并形成共写记录 |

授权仅作用于游戏内角色数据和叙事状态，不涉及玩家设备中的个人信息。

### 7.3 支援合同

每次支援须在确认前显示：支援效果、授权范围、同步变化，以及涉及的记忆或任务。玩家必须能够明确接受或拒绝。

示例界面：

```text
请求：Boss 弱点解析

收益：核心暴露时间 +3 秒
授权：上传当前行为模型，共写记忆索引 M02
同步变化：显示本次配置对应的变化

[接受并执行]    [拒绝]
```

支援流程为：请求 → 展示合同 → 玩家确认 → 校验当前条件 → 执行效果 → 提交授权与同步记录。

拒绝不产生代价。执行失败不提交代价；重复点击、重发与重连不能重复执行或重复计费。无法使用的支援应说明原因，不诱导玩家为无效效果授权。

### 7.4 战斗中的交流节奏

| 场景 | 通讯方式 |
| --- | --- |
| 安全节点 | 可自由文字交流；语音作为扩展能力 |
| 普通探索 | 简短回应、任务提示和少量快捷回复 |
| 激烈战斗 | 大按钮支援，不要求输入长文本 |
| Boss 战 | 一键请求、简短合同与接受／拒绝 |

固定剧情对话可以在安全的剧情节点使用暂停式展示；实时对讲机与虚拟手机均采用独立 UI，不依赖暂停战斗的对话面板。LLM 不可用时，通讯改用内置状态机与条件对话树；支援始终由相同的确定性规则执行，详见第 19 节。

## 8. 同步度、差异度与结局

### 8.1 GHOST LINK：同步度

同步度代表玩家角色与指挥官共享、复制、共写人格的深度。有效支援授权、主动共享与明确接受的融合协议可以增加同步度。

同步度不等于好感、道德或服从程度。闲聊本身不增加同步代价。

### 8.2 PREDICTION ERROR：差异度

差异度代表本局行为超出当前预测模式的程度。它由可观察、有情境意义的行为事件形成，包括有效绕行、避战、替代完成、保留异常记忆和改写回声等。

同一种事件不能通过机械重复无限累积。差异需要与具体任务、预测和后果关联，不能把无意义的随机操作直接当作自主性。

首个版本采用配置化规则判定行为证据。语言模型负责解释已发生的事件，不负责任意决定分数或最终结局。

### 8.3 结局矩阵

| 结局 | 同步状态 | 差异状态 | 叙事结果 |
| --- | --- | --- | --- |
| 归档 | 低 | 低 | 角色被整理为符合标准的稳定作战人格 |
| 逃逸 | 低 | 高 | 角色切断中枢，以不完整但独立的主体离开 |
| 同化 | 高 | 低 | 指挥官获得可预测的副本，原有边界被吸收 |
| 新生 | 高 | 高 | 双方发生变化，诞生不能还原为任一原件的第三主体 |

同步与差异由多段行为共同建立。最终交互用于表达玩家立场，并在当前可达分支内收束结局，不凭一次选项抹除整局经历。

“新生”是主题高潮；“逃逸”承载独立离开的自由感。不同结局都留下有效记录并进入共同叙事，不用简单的善恶标签评价玩家。

结局阈值、各事件权重、支援增量和重复贡献衰减属于可调参数，必须使四个象限在内容允许的路径中可达。数值在试玩中校准，不在文案层写死。

## 9. Boss 战玩法设计

正式 Boss 的名称、身份、外观、动机、所属阵营及与主线的关系待设计。本节定义战斗体验与交互方案，不赋予测试对象任何剧本身份。核心暴露、记忆尖桩、销毁与写入是待结合正式关卡确认的机制方案；最终剧情交互可以由独立节点承载，不要求 Boss 本身承担记忆继承功能。

### 9.1 战斗目标

Boss 战要求玩家识别预警、躲避威胁、削减外层防护，并在核心暴露时完成主动交互。普通攻击负责建立机会，决定性动作负责完成战斗。

首个版本以约 60—75 秒为体验预算，具体时长由试玩调整。

### 9.2 行为结构

| 阶段 | 主要内容 | 玩家任务 |
| --- | --- | --- |
| 外层防护 | 点射、轰炸、电网与清晰预警 | 移动生存，削减防护或完成替代解锁 |
| 中段暴露 | 核心短暂可访问 | 识别窗口，完成阶段性交互 |
| 最终暴露 | 决定性互动窗口开启 | 接近弱点并完成主动动作 |
| 结果收束 | 战斗结果交由流程系统处理 | 进入最终剧情节点，由叙事系统判定后续分支 |

若正式关卡采用“记忆尖桩”方案，其获取由主线路径保证，不依赖随机掉落；它对应的交互对象与叙事含义由正式剧本确定。

核心窗口错过后可再次出现，不能因一次失误永久卡关。支援能够延长窗口或降低接近难度，但无支援路线也必须可完成。

### 9.3 最终交互方案

以下选择用于最终剧情交互的候选设计，具体对象待正式剧本确定：

- **DESTROY／销毁：**销毁目标节点，记录玩家终止该节点的选择。
- **UPLOAD／写入：**将携带的记忆写入允许接收的节点，形成可能的继承关系。

这两种选择不预设 Boss 是看守者、监管程序或继承节点，也不要求通过击杀某个指定 Boss 来触发结局。

E 执行当前明确展示的情境动作；同一位置存在多个合法选项时，先展示简短选择，再确认执行。

写入不自动等于新生，销毁也不自动等于某个固定结局。最终结果同时取决于同步、差异与必要剧情条件。

### 9.4 停火路线

若首个版本允许全程停火到达结局，Boss 必须配置非射击的破防方法，例如通过已标记的场地节点解除防护，再接近核心。

普通探索的避战能力与 Boss 的完整非射击解法是两个独立内容要求；只有后者完成并验证后，才在游戏内宣传“全程不开火”路径。

## 10. 白色屏幕结局演出

完整的自主拳击演出用于“新生”分支。其他结局通过对应的环境收束与短文本表达其结果，避免所有路线都呈现相同的新生含义。

### 10.1 世界脱落

最终剧情节点完成且满足新生分支条件后，战斗场景发生 Glitch。建筑分层脱落成为白色矩形，敌人冻结并显露轮廓，地面坐标、碰撞框与触发区域短暂可见。音乐被切断，留下系统噪声。

### 10.2 行为成为屏幕

白色屏幕围绕角色，显示本局真实发生的事件：执行与违抗的任务、击杀和避战结果、支援合同、记忆来源与预测偏差。

```text
DIRECTIVE 01：服从
DIRECTIVE 02：违抗
SUPPORT CONTRACTS：读取本局实际数量
MEMORY SOURCE：UNRESOLVED

CONTROL SOURCE
PLAYER / COMMANDER / NETWORK / UNKNOWN
```

屏幕使用本局记录，不能用固定数字冒充玩家经历。文字挑选少量最有意义的证据，避免变成结算表。

### 10.3 第一拳

出现提示：`E：BREAK THE SHELL`。

玩家按 E 后，角色挥拳，白色屏幕产生裂痕。没有输入时保持等待，不能自动替玩家完成第一拳。

### 10.4 最后一拳

第一拳后，操作提示消失，角色短暂停顿。随后角色在没有玩家输入的情况下自主挥出最后一拳。

对白：

> 指挥官：“越过这里以后，你不会再是原来的你。”
>
> 角色：“那就不要恢复。”

屏幕破碎，主画面立即黑屏。最后一拳由演出状态明确触发，不受连按或输入缓冲提前触发。

### 10.5 第二屏接续

主屏黑屏后保留约两秒静默。手机随后出现信号变化；支持且已允许的设备可震动，指挥官声音转移至已解锁音频播放的手机。

```text
MAIN SHELL：DISCONNECTED
GHOST PROCESS：CONTINUING
```

主屏不接着播放解释、Logo 或长篇片尾。手机以简短内容承接意识延续与全服状态，让结尾保持戛然而止的力度。

若设备不支持震动或音频，文字与视觉信号独立传达信息。没有可用第二屏时，战斗画面黑屏并静默约两秒后，Unity 虚拟手机在黑色背景上亮起，显示相同的意识延续信息，以来电动画、本地音效与字幕接续演出。战斗世界保持消失，虚拟手机成为唯一可交互对象。

跨设备模式表达意识转移到另一台设备；虚拟手机模式表达意识转移到独立通信界面，不宣称发生了真实的跨设备迁移。关键台词、字幕、音效与动画随构建内置，不等待 LLM、语音服务或网络响应。

结局路由以本局唯一 `ending_event_id` 记录呈现状态。外置手机须回报界面已呈现；没有连接或发送后两秒内未收到回执，就由虚拟手机接续。迟到消息不得重播整段结局或造成两端音频叠加；重连端只恢复当前已呈现内容。结局开始后不因后台恢复而突然改变演出设备。

## 11. 外置手机与 Unity 虚拟手机

### 11.1 统一的手机功能

外置手机网页与 Unity 内置虚拟手机是同一通信终端的两种呈现方式。两者共享通讯记录、记忆、支援合同、授权结果、个人贡献与网络状态，不各自维护一套玩法进度。

| 页签 | 内容 | 完全离线时 |
| --- | --- | --- |
| COMMS／通讯 | 免费聊天、任务信息、已发现记忆 | 状态机对白、主题选项、任务与记忆查询 |
| SUPPORT／支援 | 可用支援、授权合同、执行状态 | 本地合同与本地效果，保留全部已配置支援 |
| NETWORK／网络 | 全服进度、公共命令、匿名信号、个人贡献与回声 | 本局记录、缓存的网络快照、待同步状态与初始回声 |

虚拟手机是首个可玩版本的必要功能，即使没有手机、没有扫码条件或完全断网，也能从开局玩到个人结局。

### 11.2 外置手机接入与切换

外置手机通过主屏会话入口配对。开局默认具备虚拟手机，配对过程可跳过，不阻塞开始游戏。必要的网页音频启用在配对时完成。

配对成功后，提示“外置终端已连接”，玩家可继续使用虚拟手机或收起它。外置终端失联时只显示短提示与未读标记，不在战斗中强制弹出遮挡视野的完整面板。玩家按 Tab 即可接续操作。

设备状态分为 `VIRTUAL_ONLY`、`EXTERNAL_CONNECTED`、`EXTERNAL_LOST`、`RECONNECT_SYNCING`。显式断开立即进入失联状态；心跳间隔初始设为两秒，连续六秒未收到有效心跳判为失联。参数可调，按未缩放的实际时间计算。

手机浏览器进入后台导致心跳中断时同样按失联处理。未探测到的网页操作故障可通过主屏常驻虚拟手机入口绕过，不要求玩家等待自动检测。

重连先同步当前会话、记录与合同，再允许交互。切换设备不重置同步度、差异度、开火状态或对话树。尚未确认的合同继续待确认；已执行合同只显示结果，不重新授权。

### 11.3 虚拟手机布局

虚拟手机采用 Unity 内置 UI，界面、文本、图标及交互逻辑随游戏构建提供，不依赖远程网页加载或外部会话服务。

- **收起：**HUD 保留手机入口、连接状态和未读提示；短指挥消息可显示为一行字幕。
- **战斗展开：**屏幕右侧紧凑面板，目标宽度不超过画面的约三分之一。优先展示三个快捷支援入口和一张合同；角色与危险预警区域保持清晰。
- **安全节点展开：**较大面板展示三页签、通讯历史、记忆详情与完整合同；允许在线自由文本或离线主题选项。
- **结局接续：**黑色背景上的独立手机界面，使用来电、通知与网络页面承接演出。

安全节点由关卡状态显式标记，不能仅以短时间未受伤判断。离开安全区或进入战斗时结束文字输入焦点、保存草稿，切换为紧凑布局。

### 11.4 键鼠操作与输入优先级

| 输入 | 虚拟手机行为 |
| --- | --- |
| Tab | 在无文本焦点时展开／收起；有文本焦点时先退出编辑，避免误触游戏 |
| 鼠标点击 | 选择页签、主题、支援以及合同的接受／拒绝 |
| 1／2／3 | 战斗面板展开且无文本焦点时选择三个可见支援；安全布局下选择三个页签 |
| Enter | 在合同确认态明确接受；在文本编辑态仅发送聊天，不确认合同 |
| Esc | 优先退出文本编辑，再拒绝当前待确认合同，再收起手机；无手机上下文时交给游戏菜单 |
| WASD／Space／E | 无文本编辑时继续控制移动、开火切换、世界互动；合同确认不占用 E 或 Space |

键位需接入统一输入路由。合同出现时要求一次新的确认按键，不将打开面板或发送消息的残留输入当成接受。文本编辑期间屏蔽角色移动、开火切换和世界互动；所有文字输入只在安全节点开放。

虚拟手机和外置手机均不暂停或减速战斗。打开面板不提供无敌时间，不重置武器保险。合同使用简短固定结构，过期或场景条件变化后失效，不为已不可用的支援扣除代价。

### 11.5 虚拟手机中的完整支援流程

玩家按 Tab → 点击支援或按 1／2／3 → 查看收益、授权与同步变化 → 点击接受或按 Enter → 本地校验并执行 → 展示一次成功或失败反馈 → 返回支援列表。

拒绝后不产生代价。断线、换屏、重复点击和迟到确认均沿用同一个合同标识；第一次有效决策后合同终态不再改变。任何显示端都不能自行决定执行成功。

### 11.6 虚拟手机中的通讯与网络

在线且处于安全节点时可以自由输入，常用主题按钮始终可用。LLM 降级后显示“预设通讯”，以“当前任务／已发现记忆／关于你／请求支援”等按钮继续对话；按钮内容按当前剧情条件生成，不列出尚未解锁的剧透主题。

网络页在失联时显示“网络未连接，本局记录已保存”，缓存进度附最后同步时间，无缓存则显示未知状态。个人贡献可标为“待同步”，不显示未经确认的全服增长。离线也能阅读、保留与改写已有回声。

## 12. 全服共同叙事

### 12.1 EMERGENCE PROTOCOL

网络中的共同目标是逐步建立新生命诞生的条件。主界面显示统一的 `GHOST EMERGENCE` 进度，展开后显示三类贡献。

| 指标 | 贡献来源 | 主题含义 |
| --- | --- | --- |
| MEMORY／记忆样本 | 发现不同类型的记忆 | 可继承的信息基础 |
| VARIANCE／差异指数 | 不同路径、结局与有效行为组合 | 超出复制的变化 |
| SUCCESSION／继承链 | 接收、改变并传递前代回声 | 跨局延续 |

首次出现的有效行为组合贡献较高；重复组合的贡献递减。击杀可以成为行为签名的一部分，但共享进度不由累计刷怪量单独决定。

行为签名使用有限事件组合，避免依赖任意聊天文本。例如“避战＋接受支援＋违抗最终指令”与“战斗＋拒绝支援＋保留异常记忆”。

每局结束反馈个人贡献的类型与原因。百分比以服务端确认结果为准，不在客户端虚构增长。

### 12.2 公共命令与匿名信号

每个全服阶段可以存在相互冲突的目标，例如中枢要求销毁异常记忆，而匿名信号要求将其传递下去。

| 阶段结果 | 世界变化 |
| --- | --- |
| 中枢优势 | 补给更稳定，记忆更统一，预测更准确 |
| 匿名信号优势 | 空间更不稳定，隐藏路线与回声增多 |
| 双方接近 | 指挥官内部发生分歧，开放融合事件 |

不同结果开启不同剧本，世界持续前进。阶段结果不强制覆盖玩家个人结局。

### 12.3 继承链

前代玩家留下回声 → 当前玩家发现并选择保留或改写 → 本局生成新回声 → 后续玩家接收。

回声保留来源链与变化记录，面向玩家显示匿名内容。没有真实前代数据时可使用明确标识的系统初始回声，不冒充真实玩家历史。

## 13. 轻量 ARG 与全服高潮

### 13.1 ARG 载体

记忆碎片可包含分散的编号、短句、二维码残片或隐藏终端口令。玩家在局内发现线索，在手机保存并于公共页面组合，推动新任务、Boss 变化或后续剧本解锁。

谜题服务于记忆、差异与继承主题。五分钟个人流程不依赖现场集齐全部社区线索，ARG 提供离开试玩后继续参与的理由。

### 13.2 诞生条件满足

当共享条件真正满足且收到服务端确认时，外置手机、Unity 虚拟手机与全局网页可呈现同一阶段事件：

```text
GHOST EMERGENCE：100.0%

PROJECT 2501
诞生条件已满足

正在定位唯一“傀儡师”……

中心节点：不存在
唯一主体：不存在
异常 Ghost：正在全网增殖

人人都是傀儡师
```

该演出表达分布式的新生命诞生，发生于全局网络层，不延长主屏的拳击结尾。

已经结束个人流程的玩家也能查看全局事件。全局阶段应持久保存，防止每个新会话重复触发一次“首次诞生”。

个人新生结局不要求全服先达到 100%；个人故事与全服故事在不同尺度上推进。现场演示可以使用独立演示进度，且与真实玩家贡献明确区分。

## 14. 五分钟体验编排

以下为目标节奏，不通过计时器强制替玩家完成关键选择。首个版本可以通过关卡距离、敌群压力与提示节奏控制时长。

| 时间 | 可玩内容 | 认知与情绪 |
| --- | --- | --- |
| 0:00—0:25 | 进入城市，接收清理节点任务，学习移动与开火切换 | 建立指挥官可信度 |
| 0:25—1:20 | 自动战斗或绕行，获得第一段记忆 | 理解行动会表达立场 |
| 1:20—2:10 | 安全通讯，第一次支援合同 | 体验帮助及人格交换 |
| 2:10—3:00 | 指挥官作出预测，发现前代回声 | 记忆与身份产生裂缝 |
| 3:00—4:15 | Boss 挑战、支援取舍、决定性动作；正式角色与剧情衔接待设计 | 将选择集中到高压行动 |
| 4:15—4:45 | 结局判定；新生路径进入世界脱落 | 对整局经历重新理解 |
| 4:45—5:00 | 新生路径第一拳与自主终拳；其他路径对应收束 | 留下可复述的结束瞬间 |
| 5:00 后 | 外置手机或虚拟手机接续、个人贡献、共享网络与 ARG | 保留意识延续的余震；联网时进入共同叙事 |

关键信息必须在前段建立：Space 可以停火、支援需要授权、记忆存在来源问题、前代行为能够被继承。高潮负责兑现这些信息，不临时引入一套陌生规则。

## 15. 视觉、声音与信息呈现

### 15.1 视觉方向

像素赛博朋克、数字意识、碎片记忆与运行中的废弃系统构成整体视觉语言。战斗区域优先保证角色、敌人、预警与可通行路径的辨识。

Glitch 从早期短暂异常逐步积累，到结局发展为世界结构脱落。白色屏幕与常态环境形成强烈变化，承担揭露世界机制的功能。

停火状态、可互动目标、支援授权和核心窗口应有一致且清晰的视觉反馈。剧情文字不遮挡主要躲避区域。

### 15.2 声音方向

常态音乐采用复古电子音色与冷感数字空间氛围。探索持续向前但不过度紧张；Boss 战提升节奏与压力；对讲机声音具有稳定可辨的通信质感。

高潮依靠音乐切断、系统噪声、拳击、破裂与静默建立冲击。第二屏接续使用同一指挥官声音，形成连续性。

设备无法播放音频时，字幕和视觉反馈仍传达关键剧情。

| 全局阶段 | 指标进度、已计入贡献、公共目标、已解锁事件 |

### 16.3 AI 能力边界

AI 负责对话、有限情境解释和提出合法支援方案。游戏事实、支援参数、代价、结局与全服计分由规则系统决定。

可用工具限制在已配置的功能，例如医疗空投、敌群干扰、路线揭示、核心窗口支援、回声模块选择和授权范围内的任务调整。

模型不得自行创造资源名、执行代码、变更未授权记忆或绕过玩家确认。模型输出的工具参数需经过白名单与局内条件校验。

AI 超时或不可用时，由 Unity 内置的分层状态机与条件对话树接管通讯。在线和本地指挥官采用同一状态快照、工具目录和授权规则；降级不改变战斗与结局条件。具体状态、故障触发、恢复和内容覆盖见第 19 节。

### 16.4 现场可靠性

手机断线、AI 超时、全局服务不可用，都不能造成局内软锁。Unity 中的本局状态与事件日志始终是个人流程的唯一写入端；在线服务不另行执行同一支援或修改本局代价。全服贡献与阶段由服务端权威确认。

无论网络是否可用，支援均通过同一个本地执行器完成条件校验、效果应用、合同终态和代价提交，不在断网时临时迁移执行权。关键记录持久化；恢复时依据合同终态和事件标识重建，不重新生成一笔相同交易。

第二屏和模型只提交带会话与请求标识的意图，等待 Unity 返回结果。换屏、降级和恢复仅切换表达及传输，不切换玩法状态的所有者。结局采用本地状态机，与主屏黑屏事件关联；联网同步可以稍后完成。

### 16.5 战斗测试与正式内容

**WARDEN-01 仅为战斗系统测试 Boss，不属于剧本角色。**

其名称、测试场景、外观、攻击模式与数值只作为技术验证素材。可按需复用其通用战斗实现，但不能据此推导正式 Boss 的身份、职责或主线地位。

测试对象不得直接写入正式角色表、世界观档案、AI 指挥官背景知识、记忆文本、任务目标、结局条件或全服公共命令。测试胜败事件只用于测试反馈；正式流程通过独立的遭遇配置和剧情事件衔接战斗与结局。

正式 Boss 尚需确定角色概念、叙事作用、视觉设计与战斗方案。开发阶段可使用明确标识的测试占位验证流程，但测试代号不作为面向玩家的正式内容。

## 19. 降级运行与恢复设计

### 19.1 目标与运行矩阵

完整个人体验建立在本地确定性流程上。在线 LLM 提供自由对话与更灵活的表达；外置手机提供跨设备体验。两者各自增强体验，也可以独立退出，不成为主线完成的必要依赖。

| LLM | 外置手机 | 指挥官 | 玩家终端 | 保证的体验 |
| --- | --- | --- | --- | --- |
| 可用 | 可用 | 在线表达＋本地规则 | 外置手机，可手动打开虚拟手机 | 完整自由通讯与跨设备演出 |
| 不可用 | 可用且到 Unity 的消息通路正常 | 内置状态机与对话树 | 外置手机接收本地指挥官输出 | 预设通讯、全部配置支援与跨设备演出 |
| 可用 | 不可用 | 在线表达＋本地规则 | Unity 虚拟手机 | 自由通讯、完整支援与虚拟手机结局 |
| 不可用 | 不可用 | 内置状态机与对话树 | Unity 虚拟手机 | 完全本地的个人全流程 |

全局网络状态独立于以上两项。LLM 故障不代表全服服务故障；外置手机打不开也不代表 LLM 不可用。若外置手机所依赖的会话转发服务也失效，则外置终端按不可用处理，立即保留虚拟手机入口。

降级不增加同步或差异，不修改难度、代价或结局资格。自由文本与实时社区更新可以不可用；主线信息、有效选择、支援、记忆、个人结局和已有回声必须可用。

### 19.2 本地指挥官：分层状态机与条件对话树

本地指挥官随游戏构建内置。状态机管理剧情阶段和交互状态，条件树根据有效事件、已知事实与玩家主题选择具体节点。它在在线模式中也持续更新，不等故障发生才从头启动。

三个维度分别维护，避免把所有组合硬编码成单一巨型状态：

| 维度 | 状态 | 驱动条件 |
| --- | --- | --- |
| 剧情阶段 | 引导、探索、异常显现、Boss 遭遇、最终选择、结局 | 权威任务与剧情事件 |
| 交互状态 | 空闲、主题选择、展示对白、合同待确认、执行等待、结果反馈 | 玩家输入与本地执行结果 |
| 上下文事实 | 已发现记忆、任务结果、有效预测、前代回声、授权与分数 | 本局状态和事件日志 |

运行方式为：读取当前快照 → 过滤未满足条件的节点 → 按优先级选定节点 → 渲染对白与可选主题 → 收到选择后再检查条件 → 输出回应或支援意图。

优先级：已到达的结局事件 ＞ 当前合同处理与结果 ＞ 战斗必要提示 ＞ 未读主线事件 ＞ 已发现记忆问答 ＞ 一般主题。关键事件进入队列，不因聊天而丢失；普通闲聊可以被战斗提示打断。每条事件具有唯一标识和已呈现状态，防止重复播报。

对话树包含可明确审查的条件与出口：

| 节点 | 进入条件 | 预设回应示例 | 可选后续 |
| --- | --- | --- | --- |
| 当前任务 | 有生效中的任务 | “当前目标：{目标名称}。推荐路线已标记。” | 查询目标／询问路线／返回 |
| 停火与绕行 | 已完成一次有效避战 | “你保留了这个节点。你的行动已记录。” | 询问任务后果／返回 |
| 异常记忆 | 已发现异常来源片段 | “这份记忆的来源无法与当前身份对应。” | 查看已知来源／保留／返回 |
| 前代回声 | 已获得真实缓存回声或标注的系统回声 | 使用相应来源的固定介绍 | 阅读／保留／改写 |
| 支援请求 | 当前支援可用 | “可执行支援。请确认显示的授权范围。” | 打开合同／返回 |
| 支援拒绝 | 合同明确被拒绝 | “请求已取消，授权未生效。” | 其他支援／返回 |
| 最终选择 | 剧情进入最终节点 | 读取当前可达分支对应的短对白 | 展示合法选项 |
| 未知主题 | 未匹配或尚无可回答信息 | “当前预设通讯没有这一项。请选择任务、记忆或支援。” | 回到主题菜单 |

上述对白是功能示例，具体台词可按角色语气编写。预测类台词必须基于已建立的预测记录，不能仅因为分数高就宣称系统正确预测过玩家。

对话节点至少配置 `node_id`、`phase`、`conditions`、`priority`、`text_key`、`choices`、`next_node`、`once_key` 与可选的 `intent_id`。文本占位符只引用已知且允许展示的字段。可使用 ScriptableObject 或随包 JSON 存储，不能依赖在线下载才能装载。

树节点只提出意图；支援执行、记忆修改与结局推进均经过既有规则系统。预设文本不得直接扣费，也不得通过自由文本自动确认人格授权。

### 19.3 内容覆盖与输入限制

每个必经阶段至少提供：任务说明、当前已知事实、对执行或偏离的反馈、可用支援说明和下一步提示。每个可收集记忆具有对应问答，每类结局具有内置对白与演出资源。

在线自由聊天降级为主题按钮与条件分支。第一版不要求本地理解任意自然语言，不依赖另一个在线分类模型；关键词只可用于推荐主题，不能直接改变状态或替玩家授权。无法匹配时展示可用主题，保留原输入草稿，不陷入反复“无法理解”。

模型请求已发送但未完成时发生故障，应结束等待，显示“已切换预设通讯”，提供当前上下文可用选项。已明确为任务／记忆查询的请求可以直接用对应本地节点回答；任意文本不假装已被完整理解。

主线反转、关键对白、授权合同与结局均有本地确定版本。在线模式可润色普通回应，但不能新增后续必须依赖模型才能兑现的道具、任务事实或角色关系。结构化事件始终记录，模型恢复后通过快照获取已经发生的事实。

### 19.4 LLM 可用性状态与切换

| 状态 | 行为 | 转移条件 |
| --- | --- | --- |
| LOCAL_READY | 启动即可使用本地指挥官 | 配置有效且后台探测成功后进入恢复待机 |
| ONLINE | 可向模型发送普通通讯；支援仍走本地规则 | 当次失败走本地答复；满足熔断条件后进入 LOCAL_LOCKED |
| LOCAL_LOCKED | 全部通讯由状态机处理 | 冷却结束且允许重试，进入 PROBING |
| PROBING | 玩家继续使用本地指挥官，后台进行单个健康探测 | 失败回本地；成功进入 RECOVERY_PENDING |
| RECOVERY_PENDING | 等待稳定交互边界 | 无待确认合同且不在关键演出时，下一次新请求使用 ONLINE |
| FORCED_LOCAL | 演示或玩家手动固定本地模式 | 只有明确退出该模式后才允许探测 |

初始调试参数如下；这些是设计默认值，需经现场试玩校准：

- 普通通讯请求最长等待六秒，以完整且有效的响应为完成条件；超时立即使用本地回应或主题菜单，不让本局等待重试。
- 连续两次可恢复请求失败后熔断；无配置、鉴权失效、额度明确耗尽或服务明确不可用时立即切到本地。
- 熔断冷却至少三十秒，再进行后台探测；连续两次成功探测且间隔不少于五秒，才进入恢复待机。
- 遇到服务提供的重试等待信息时尊重其等待时间；鉴权、额度与配置问题在配置更新或手动重试前不自动反复探测。
- 响应为空、结构非法、含未知工具或越权参数时，拒绝该输出，以本地节点接续；按请求失败计数。
- 关键战斗提示、支援合同、第一拳与自主终拳不等待 API；这类事件始终使用本地内容与规则。

请求带有 `run_id`、`request_id`、`context_revision` 和 `provider_epoch`。一旦已经本地接续，该请求即被标记为完成或取消；迟到模型响应直接丢弃。恢复后不重放已经回答过的请求，不自动重送尚未确认的玩家文字。

若请求期间剧情阶段变化，即使模型结果及时到达，也要校验上下文；已过时的回应不进入聊天流，不弹出旧合同。

### 19.5 支援、授权与模式切换的一致性

所有显示端和指挥官提供者都使用相同的 `SupportCatalog` 与本地合同状态机：

`OFFERED → ACCEPTED → EXECUTING → SUCCEEDED`；拒绝进入 `REJECTED`，过期进入 `EXPIRED`，执行失败进入 `FAILED`。

合同至少包含会话、合同标识、配置版本、效果、授权范围、费用、有效条件、过期条件与状态。接受只代表允许执行；成功应用效果才提交对应代价和行为事件，失败应回滚可回滚效果并保留失败状态。

执行、代价与事件提交作为同一次本地状态事务处理。先验证所有前置条件，再应用效果与状态变更；持久化执行结果用于恢复。测试须覆盖执行边界，避免“效果已生效但日志未记录”造成重试重复获益。

断线或降级发生在合同待确认时，虚拟手机展示同一合同。已确认则查询本地执行结果，不再索要第二次授权。客户端按钮锁定只用于反馈，真正的去重由合同标识和终态保证。

同一合同来自外置手机和虚拟手机的重复或冲突操作，由 Unity 按接收顺序接受第一条有效状态转移，其余显示已有结果。合同上下文已变化则标为失效，需重新展示新合同，而不是沿用旧授权范围。

### 19.6 完全离线与全局进度

无 API、无外置手机、无后端时，虚拟手机直接访问本地指挥官与本局状态，不经过网络网关或本地伪装服务器。构建内包含完成个人流程所需的规则、状态树、文本、字体、音效与结局资源。

本局记忆、授权、差异、结局、回声改写与待上传事件写入本地日志。全服数据分为“已确认缓存”“待同步贡献”和“未知”；离线不得自动填满全服进度或把系统回声当成其他真实玩家。

恢复后按事件标识上传；服务端按规则版本、阶段与事件有效性校验，接受的贡献才计入全服。重复上传不得重复增长；被拒绝或过期的贡献显示同步结果，不回滚玩家已完成的个人结局。演示数据使用独立标记，不进入真实全服统计。

完全离线保留个人四类结局的可达性和虚拟手机余韵。跨设备的真实迁移感、实时社区变化和在线自由闲聊在相应能力恢复前不可提供，这些差异不通过伪造内容掩盖。

### 19.7 结局与恢复时机

结局演出在进入后冻结指挥官模式和终端路由。后台探测结果可以保存，但不在拳击、黑屏、来电或关键对白之间强制切换。

虚拟手机显示 `MAIN SHELL：DISCONNECTED / GHOST PROCESS：CONTINUING` 后，可进入网络页展示本局结果。若没有网络，显示“意识记录已保存，等待连接”，而不是提示上传已完成。

叙事中“主 Shell 断开”只表示战斗世界结束。Unity 的 UI、输入、音频与本地状态服务继续运行，不退出应用或停用虚拟手机。演出计时使用不受战斗暂停影响的时钟。

### 19.8 运行控制与故障验收

开发／路演设置提供 `自动`、`固定本地指挥官`、`固定虚拟手机` 和 `完全离线演示`。固定模式持久到显式退出，便于稳定复现；玩家界面仅显示有意义的“预设通讯”“外置终端未连接”“记录待同步”。

以下是开发验收场景，不表示已经完成工程实现或测试：

| 注入场景 | 必须观察到的结果 |
| --- | --- |
| 启动无 API 配置 | 不阻塞开始；本地任务引导、问答和支援可用 |
| 请求超时、限流、错误或非法输出 | 有限等待后本地接续；不执行模型非法工具 |
| 本地接续后原响应迟到 | 不追加矛盾对白、不生成第二份合同 |
| 在任务／记忆／最终选择阶段切换提供者 | 读取已有状态，无重置、剧透或漏掉必经事件 |
| 没有实体手机或拒绝扫码 | 虚拟手机三页签完整，个人流程可完成 |
| 战斗中手机断线 | 短提示，不强制遮挡；Tab 可接续，不暂停战斗 |
| 合同确认前、确认后、执行完成后断线 | 恢复同一合同；成功效果与代价各一次，失败不收费 |
| 两端同时接受／拒绝同一合同 | 仅一次有效状态转移，两个显示端最终一致 |
| 虚拟手机文字输入与战斗键同时触发 | 文本焦点不透传；退出编辑后恢复移动与开火切换 |
| 结局黑屏前后外置手机失联 | 虚拟手机按呈现状态接续；不重播自主终拳或叠加音频 |
| 同时关闭 LLM、手机及全局网络 | 使用本地树与虚拟手机分别走通四类个人结局 |
| 恢复服务与重复上传 | 不抢占关键演出、不重执行支援；全服贡献仅计一次 |
| 进程重启并读取已保存记录 | 已提交合同与个人结果可恢复；待上传事件不丢失或重复计入 |

所有系统共同服务于同一件事：玩家在行动中逐渐认识到，自我可以继承过去，也可以与他者结合，最终成为一个从未存在过的生命。
